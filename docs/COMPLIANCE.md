# 合规审查

当前源码支持启用合规审查、保存工程项目档案、导入资料快照、人工核对资料角色与选用版本，以及四组规则、扫描识别、批次预算、原文证据、人工确认卡和固定批次的 HTML/Excel 报告。源码完成不表示运行实例已经部署。

## 开始使用

1. 打开“设置 → 内置能力”，勾选“启用合规审查”。
2. 选择对话模型。可创建专用助手，也可明确关联已有助手身份。资料识别模型可暂不配置。
3. 保存设置。启用和保存不会发起检查或识别请求。
4. 选择工作目录，点击“打开合规对话”。在该聊天中使用“工程项目档案”，或请助手通过 `compliance_project` 建立档案。

一个专用助手负责四个 Skill：资料整理、合规检查、问题复核和报告生成。Skill 说明不代表对应业务已经执行，实际进度以资料、批次和操作回执为准。普通聊天在资源发现前排除这些资源，不新增合规工具定义、Skill 索引或说明。子 Agent 不继承专用会话资格。

## 工程项目档案

档案具有独立稳定编号。项目名称、业务编号、单位、年度、期次、项目类型和项目阶段分别保存。缺少的字段保留未知。审查人员核对项目身份，并逐项选择四组规则是适用、不适用或尚未确认。

保存使用当前修订和稳定操作编号。重复提交相同内容返回原回执；同一编号换成其他内容会被拒绝。其他聊天已经更改记录时，需要重新核对。档案独立于聊天保存，聊天正文继续由 Pi 原生会话管理。

## 导入资料和核对范围

在专用聊天的“工程项目档案”中选定工程项目，可选择本机 PDF、PNG/JPEG/WebP、XLSX 或 UTF-8 CSV；也可输入当前授权工作目录内明确的相对文件路径，或刷新并选择当前聊天的办公附件。目录入口只导入列出的文件。OFD、CEB、旧式 Office 和压缩包需要先转换。

导入保存不可变原件，原路径后续变化不会改变旧批次。相同工程项目的相同字节复用同一份快照；不同字节分别保留。同类资料有多份时，逐份选择角色、勾选“归属已核对”和“选用于新批次”，保存资料核对。同类多份同时选用会明确要求核对唯一版本。助手可以整理资料和档案元数据，工程身份、规则适用性及资料选用须由审查人员在工作台确认；修改身份字段后需重新核对。

CSV/XLSX 使用第一行固定表头，每行保存明确的文字值。模板如下；XLSX 同样使用这些表头，日期单元格请设为文字，公式和缓存结果不作为字段事实。

```csv
项目名称,项目编号,单位,年度,期次,项目类型,阶段,本次规则适用清单,日期,文号
示例工程,P-001,示例单位,2026,一期,市政工程,可研,合同签订期限=待确认,2026-08-01,
```

项目类型、阶段和规则适用清单保留原文及单元格出处。规则适用清单可写各规则的适用状态。导入只产生候选；请在工程项目档案中逐项核对并保存，不自动改变工程身份或适用性确认。

文本 PDF 只从明确的“项目名称：”“日期：”“签订日期：”“评审日期：”等标签提取字段；未匹配、缺年份或冲突的内容保留未知。日期可精确到日或月，不补造具体日期。台账的文号文字不代替发文首页上方的证据。扫描件或无可靠字段时使用批次固定的图像模型提取候选；未配置或不可用时保留明确原因，不以空文字认定文号缺失。

单份原件不超过 20 MiB；每个工程项目最多 32 份、256 MiB；所有合规原件合计最多 2 GiB、一万个对象。上传按文件逐份提交，已成功保存的原件会保留。超过容量时拒绝新写入，不自动删除旧资料。文本检查每份最多二百页，超出或读取截断时不能给出确定性通过。

## 文本检查与证据

点击“按已核对资料创建检查批次”。批次固定当时的项目身份和适用清单、实际选用快照、规则内容与版本、模型配置引用及原文字段。补充资料、换版本或换规则后另建批次，历史批次可单独查看。纯文本字段足够时不调用模型；扫描图片及尚未取得必要字段的 PDF 按需使用已配置的识别模型。

对话模型记录该专用聊天当时的实际选择。通过 API 建立检查且未关联活跃的原生聊天时，对话模型记为未知，不回填设置中的初始默认值。旧批次保持原记录。

四组检查分别是资料缺失与归属、可研评审及批复文号、合同期限、可研报告与评审时序。合同按自然日差计算，通知书当日为第零天，零至三十日通过，负数和第三十一日起分别列为候选问题。可研报告须严格早于评审，同日列为候选问题。只有月份时按当月可能日期区间判断，区间交叠或跨越期限边界时为证据不足。

文号通过要求可核实的发文首页上方完整文号，证据保留真实页码与旋转后的页面位置。无文字、位置证据不完整或图片不清时为证据不足。审查人员确已查看首页、确认缺失时，可以明确保存“已查看发文首页并确认文号缺失”，检查将列出候选问题。

结果区分通过、发现候选问题、证据不足和不适用；解析执行失败另行标明，初始结果保留未人工复核状态。“查看证据”显示原件名称、页码或工作表行、原文和日期精度。归属冲突也提供相关字段证据。能力未配置识别时图片保留待识别原因，其他可读文本仍可检查。

## 字段修正与人工结论

在批次结果下使用“人工复核”。选择资料和字段，填写人工值、原件页码或工作表行列、原文说明与核对理由，然后点击“准备确认卡”。也可从“查看证据”进入字段修正。原始提取没有字段时，仍可选择本批次内的明确资料和字段补充。日期只写到月时保持月精度。确认文号缺失须明确核对发文首页上方，不能用读取失败代替缺失。

确认卡显示工程编号、批次修订、原始提取、此前人工值、本次人工值或人工结论、理由、资料哈希、规则版本和来源聊天。请逐项核对，再点击“确认并提交”。助手的 `compliance_review` 工具只能准备、列出或查询方案与回执，不能提交人工确认。来源聊天不同、能力停用、资料或规则绑定变化、批次已有新修订时，旧卡须重新准备。检查仍在实际运行时不能修改该工程的批次。

原始提取与人工核对值分别保存。修正后按本批次固定的资料、项目、规则和配置重新计算，产生新修订并重置当前结论的复核状态。旧修订及人工确认保留在历史中。对尚不可读资料，只有相关规则所需输入全部明确人工核验后，该规则才可使用这些值；原件的读取失败或未识别状态仍保留。继续未启动步骤也保留人工值，并把此前人工结论存入历史。

选择“确认人工结论”可对某条规则作出人工决定。系统建议与人工结论分别显示，可以不同。确认部分规则时显示“部分人工确认”；全部规则均确认后显示全部已确认。网页断线或响应未知时点击“查询原操作回执”，不重新发送未知操作。重复相同操作返回原回执；变更内容须准备新卡。

## 扫描识别、预算与检查点

在设置中单独选择支持图像输入的资料识别模型。新批次固定该选择，不自动换用其他模型。图片和所需 PDF 页先经同一个无凭据解析池渲染，再发送有尺寸与传输量限制的 PNG；缺少原生渲染能力、页面不完整或不可解码时明确失败。每页最多约四百万像素、四 MiB PNG，源图像受三千二百万像素限制；批次累计编码图像传输量不超过一百二十八 MiB。模型仅返回受字段 schema 和已发送页面范围校验的候选，不取得写入或人工确认工具。识别候选的文号仍须位于发文首页上方；模糊或未知保持证据不足。

批次默认预算为二百页处理量、二十次模型调用、十分钟运行时间。创建批次前可修改；PDF 文字读取与页面识别分别计入页处理量。预算限制下一步骤准入，当前步骤仍须实际结束，因此不是供应商账单或绝对墙钟上限。结果区显示已处理页数、调用次数、运行时间和暂停原因。实际账单未知时明确显示未知；取得的模型目录费用估算另行标明，不把默认零价格解释为免费。

识别返回的字段不合法时，步骤仍是失败。已取得的 token 用量保留；实际账单未知时继续标为未知。

达到预算后保存进度并暂停。点击“追加当前预算，继续未启动步骤”才增加额度并安排尚未启动的工作；已经完成、失败或结果不确定的步骤不自动重试。界面也提供当前步骤结束后暂停。资料、模型或规则需要更换时建立新批次。

## 报告与独立保存

在批次结果下点击“生成 HTML 与 Excel”。报告绑定当时的批次修订，包含项目快照、规则内容与版本、生成时间、所有规则结论与执行状态、人工复核状态、日期原文与精度、证据页码或工作表行，以及未完成项和原因。证据不足、不适用和执行失败均保留；生成报告不更改批次，也不表示检查全部通过或已经人工确认。重复生成使用新文件名，旧报告不覆盖。

“已生成”表示私密报告字节已保存。可预览 HTML 或下载两种原件；HTML 使用无同源与脚本权限的沙箱。Excel 使用固定表头与文字单元格，没有公式、宏或外部链接。需要通过文档工具核对 Excel 时，先把下载的文件重新上传为当前聊天附件，再用 `read_document` 读取；报告私密路径、成果 ID 都不能代替附件资格。

点击“交付到当前聊天”后，由该专用聊天的唯一受管 worker 登记原生交付引用。服务器生成快照、原生登记和独立保存是不同步骤；登记未确认时显示“快照已发布 · 原生登记待核对”。未知结果先查询原操作，页面不会自动重发。

“已交付 · 待独立保存”仍依赖原生会话分支。点击“保存到成果中心”沿现有来源资格建立独立副本，成功后显示“已保存到成果中心”。保存失败不更改检查结论。独立成果在停用能力或删除来源聊天后仍按[成果中心](ARTIFACTS.md)权限预览、下载。

保存核对本报告的精确原生交付和文件哈希。同名、同大小的其他交付不能代替当前来源。若交付已变化，请刷新报告后再核对。

报告含待核对的预留最多五百份、合计 2 GiB。HTML 限 2 MiB，Excel 单元格限 32767 字符；超过时拒绝生成，不截断冒充完整报告。交付仍限每件 16 MiB、每组 64 MiB。中断生成的预留和未知对象继续占额度，不自动清理或重放。

## 停用和恢复

能力默认关闭。检查期间可请求停用，界面先显示“停用中”，当前步骤真实结束并保存检查点后停用，不再安排下一步。即使当前步骤结束前再次启用，原批次也按停用请求暂停，需显式继续。资料导入期间也可请求停用；当前资料校验结束后停止，本次选择的一组资料不部分发布，之前已成功导入的资料保留。快速重新启用不会恢复该次导入。停用保留档案、绑定和模型配置；再次启用复用同一个助手，保留用户修改的名称和行为说明。可在“助手身份”中编辑这两项内容。

开关状态与本地可用条件分开。配置不足表示专用助手、对话模型或共享解析组件不可用；部分可用表示文本检查可用，但扫描识别尚未配置或缺少所需组件；本地条件可用表示当前助手、模型目录和组件满足准入要求。这个状态不代表供应商已响应，也不代表识别准确率或真实费用已验收。停用后仍可读取历史档案、原件及报告。原件读取和导入均参与活动与维护空闲判断，停机等待实际读取和校验结束。

已有运行实例应在空闲时重载资源。服务器会拒绝停用后的合规工具调用。网页断开不取消当前工作。未确认的网络结果先查询原操作，浏览器不会自动重发未知写入。服务重启后执行中请求标为“请求待核对”，保留已完成检查点；该状态指请求结果不确定，与结论的人工复核状态分开。读取、原操作重复查询或显式继续都不重发不确定请求。首次配置的助手绑定有持久准备记录，可按原操作继续核对。原生会话创建有独立操作标记，重试先查原生记录，结果不确定时不会再创建一个聊天。

状态和不可变原件保存在实际 Agent 身份目录下受保护的 `pivane-compliance/` 中。请把整个目录视为用户数据，随身份一起备份。另有五百个工程项目、五百个检查批次、两千份复核方案、一万个操作回执、八 MiB 账本上限，达到限制时明确拒绝保存。未提交的原件对象也占用原件容量，不据此冒充已成功导入。

# 合规审查

当前源码支持启用合规审查、保存工程项目档案、导入资料快照、人工核对资料角色与选用版本，以及四组文本规则和原文证据。源码完成不表示运行实例已经部署。扫描识别、字段修正与最终结论确认、报告导出仍待后续实现。

## 开始使用

1. 打开“设置 → 内置能力”，勾选“启用合规审查”。
2. 选择对话模型。可创建专用助手，也可明确关联已有助手身份。资料识别模型可暂不配置。
3. 保存设置。启用和保存不会发起检查或识别请求。
4. 选择工作目录，点击“打开合规对话”。在该聊天中使用“工程项目档案”，或请助手通过 `compliance_project` 建立档案。

一个专用助手负责四个 Skill：资料整理、合规检查、问题复核和报告生成。当前尚未提供的工具会明确显示不可用，Skill 说明不代表对应业务已经执行。普通聊天在资源发现前排除这些资源，不新增合规工具定义、Skill 索引或说明。子 Agent 不继承专用会话资格。

## 工程项目档案

档案具有独立稳定编号。项目名称、业务编号、单位、年度、期次、项目类型和项目阶段分别保存。缺少的字段保留未知。审查人员核对项目身份，并逐项选择四组规则是适用、不适用或尚未确认。

保存使用当前修订和稳定操作编号。重复提交相同内容返回原回执；同一编号换成其他内容会被拒绝。其他聊天已经更改记录时，需要重新核对。档案独立于聊天保存，聊天正文继续由 Pi 原生会话管理。

## 导入资料和核对范围

在专用聊天的“工程项目档案”中选定工程项目，可选择本机 PDF、PNG/JPEG/WebP、XLSX 或 UTF-8 CSV；也可输入当前授权工作目录内明确的相对文件路径，或刷新并选择当前聊天的办公附件。目录入口只导入列出的文件。OFD、CEB、旧式 Office 和压缩包需要先转换。

导入保存不可变原件，原路径后续变化不会改变旧批次。相同工程项目的相同字节复用同一份快照；不同字节分别保留。同类资料有多份时，逐份选择角色、勾选“归属已核对”和“选用于新批次”，保存资料核对。同类多份同时选用会明确要求核对唯一版本。助手可以整理资料和档案元数据，工程身份、规则适用性及资料选用须由审查人员在工作台确认；修改身份字段后需重新核对。

CSV/XLSX 使用第一行固定表头，每行保存明确的文字值。模板如下；XLSX 同样使用这些表头，日期单元格请设为文字，公式和缓存结果不作为字段事实。

```csv
项目名称,项目编号,单位,年度,期次,日期,文号
示例工程,P-001,示例单位,2026,一期,2026-08-01,
```

文本 PDF 只从明确的“项目名称：”“日期：”“签订日期：”“评审日期：”等标签提取字段；未匹配、缺年份或冲突的内容保留未知。日期可精确到日或月，不补造具体日期。台账的文号文字不代替发文首页上方的证据。扫描件或无可读文字时保留原件并说明需要识别，不以空文字认定文号缺失。

单份原件不超过 20 MiB；每个工程项目最多 32 份、256 MiB；所有合规原件合计最多 2 GiB、一万个对象。上传按文件逐份提交，已成功保存的原件会保留。超过容量时拒绝新写入，不自动删除旧资料。文本检查每份最多二百页，超出或读取截断时不能给出确定性通过。

## 文本检查与证据

点击“按已核对资料创建检查批次”。批次固定当时的项目身份和适用清单、实际选用快照、规则内容与版本、模型配置引用及原文字段。补充资料、换版本或换规则后另建批次，历史批次可单独查看。创建文本批次不会调用模型。

四组检查分别是资料缺失与归属、可研评审及批复文号、合同期限、可研报告与评审时序。合同按自然日差计算，通知书当日为第零天，零至三十日通过，负数和第三十一日起分别列为候选问题。可研报告须严格早于评审，同日列为候选问题。只有月份时按当月可能日期区间判断，区间交叠或跨越期限边界时为证据不足。

文号通过要求可核实的发文首页上方完整文号，证据保留真实页码与旋转后的页面位置。无文字、位置证据不完整或图片不清时为证据不足。审查人员确已查看首页、确认缺失时，可以明确保存“已查看发文首页并确认文号缺失”，检查将列出候选问题。

结果区分通过、发现候选问题、证据不足和不适用；解析执行失败另行标明，结果均保留未人工复核状态。“查看证据”显示原件名称、页码或工作表行、原文和日期精度。归属冲突也提供相关字段证据。能力未配置识别时图片保留待识别原因，其他可读文本仍可检查。

## 停用和恢复

能力默认关闭。停用保留档案、绑定和模型配置；再次启用复用同一个助手，保留用户修改的名称和行为说明。可在“助手身份”中编辑这两项内容。

已有运行实例应在空闲时重载资源。服务器会拒绝停用后的合规工具调用。未确认的网络结果先查询原操作，浏览器不会自动重发未知写入。首次配置的助手绑定有持久准备记录，可按原操作继续核对。原生会话创建有独立操作标记，重试先查原生记录，结果不确定时不会再创建一个聊天。

状态和不可变原件保存在实际 Agent 身份目录下受保护的 `pivane-compliance/` 中。请把整个目录视为用户数据，随身份一起备份。另有五百个工程项目、五百个检查批次、一万个操作回执、八 MiB 账本上限，达到限制时明确拒绝保存。未提交的原件对象也占用原件容量，不据此冒充已成功导入。

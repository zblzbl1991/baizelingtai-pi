# WeKnora 知识库

当前源码提供独立知识库页面与聊天检索入口，复用[Pi 原生 MCP](MCP.md)中已经配置的服务。源码实现不表示运行实例已经升级；本功能尚未公开发布。

## 配置与打开

1. 在“扩展 → MCP”添加内置 WeKnora，刷新后编辑 `WEKNORA_BASE_URL`（含 `/api/v1`）和 `WEKNORA_API_KEY` 并启用，即可连接 WeKnora 0.7 REST 服务，无需另开 MCP 进程；详见[内置配置](MCP.md#内置-ocr-与-weknora-stdio)。也可沿用自行配置的 stdio MCP，或在新版 WeKnora“设置 → 发布与集成 → MCP Server”创建 HTTP 端点。不在知识库页另存地址或凭据。
2. 在聊天中打开一个持久线程。进入“扩展 → 知识库”，也可以从聊天输入框的添加菜单选择“知识库检索”。页面不会为关闭的线程启动 worker。
3. 页面默认选择已配置的 WeKnora 服务。已有可用工具时自动加载知识库列表；重启后页面先于会话恢复打开，也会在连接恢复后自动加载。打开时对话正在运行，则等待空闲。工具尚未就绪时先核对原生 MCP 状态：启动中最多观察约 10 秒；确认所选 WeKnora 处于未连接状态后，自动连接一次并加载列表。失败、需要登录、状态不确定或仍未就绪时停止，可手动“连接所选服务”或刷新核对。“连接设置”中提供刷新配置、让助手配置和管理 MCP。保存配置不会自动更新已打开的线程，必要时重载线程资源。
4. 左侧显示可访问的知识库、服务返回的说明与文档数量，可按名称筛选并勾选最多 10 个知识库组合检索。名称筛选只改变列表显示，不清除已选范围；右侧持续显示当前检索范围。列表每页 20 项，有后续页时点击“更多知识库”，“刷新列表”重新读取首屏并清除范围选择。切换服务或关闭页面也会清除选择。
5. 填写“检索关键词”后“搜索知识库”。选择多个知识库时依次读取每个库，合计最多展示 200 项，按请求范围归集并保留实际来源，不做跨库相关性重排。内置服务使用已加载的每库召回设置（1–20，默认 5）；其他端点通常每库最多请求 10 个片段。任一请求失败即停止，本批结果不展示，不自动重试。支持全库搜索的端点提供“所有知识库”；已加载默认范围的内置服务提供“使用服务默认范围”。未保存默认库的内置服务和旧版 `hybrid_search` 需要先勾选范围，以实际参数 schema 为准。只选择一个知识库时还可“浏览文档”，文档列表每页 20 项。

打开页面读取脱敏配置与已有 worker 的工具目录，并在所选服务具备列表工具时自动读取知识库首屏；切换可用服务或手动连接成功后也会加载。自动连接仅针对已配置、启用且可识别的所选 WeKnora，每个会话连接代次、每个服务最多一次，不自动登录、检索或读取文档正文。没有打开的持久线程时不创建 worker；系统恢复原会话后自动续接列表加载。切换线程时丢弃旧结果，待原请求完成再加载新范围；关闭页面停止后续自动操作。读取、连接失败或结果不确定不自动重放，仍可手动核对和连接。项目配置遵守项目信任，隐藏、禁用、白名单排除的工具不会通过页面获得调用权限。配置中存在服务不表示当前线程已加载相应工具。

## 助手检索设置

选择内置 WeKnora 服务后，展开“助手检索设置”。左侧勾选用于检索的库，点击“使用左侧已选范围”，再调整参数并“保存检索设置”。页面临时筛选不会自动保存为助手默认范围。

如果提示“当前后端尚未加载检索设置功能”，说明页面已经更新，但后端进程仍使用旧模块。先从原启动入口按正常停机流程重启后端，再点击“重新检查设置”；仅刷新网页或重载对话资源不能更新后端服务。后端声明支持后，页面才根据所选服务是否为内置 WeKnora 展示编辑器或自建服务说明。

| 设置 | 初始值与作用 |
|---|---|
| 默认检索范围 | 最多 10 个真实知识库 ID；初始不固定，由助手按对话指定。未在本次 MCP 调用提供 `kb_id` 时，工具依次检索已保存的默认库。明确提供 `kb_id` 可覆盖本次范围，不是权限白名单 |
| 每库召回条数 | 1–20，默认 5；条数越多，召回范围越广 |
| 向量匹配阈值 | 0–1，默认 0.5；越高越严格，可能减少语义相关的结果 |
| 关键词匹配阈值 | 0–1，默认 0.3；越高越严格，可能减少关键词匹配结果 |

设置跟随所选内置服务保存在原生 `mcp.json` 的 `env.WEKNORA_SEARCH_SETTINGS`，使用私密原子保存、范围和修订校验，保留 URL、Key 及其他字段。全局服务影响使用该服务的所有项目；受信项目自己的完整服务配置只影响该项目。继承全局服务时编辑全局配置，不隐式复制凭据到项目；自建 stdio／HTTP MCP 不使用此内置设置，需在相应服务配置默认参数。

保存只改变配置。空闲后重载当前对话资源或新建会话，原生 MCP 进程才会读取新值；不自动重载或中断任务。当前工具 schema 与说明反映实际加载的设置：没有默认库时仍要求明确的 `kb_id`；已有默认库时可省略。显式传入的 `limit`、`vector_threshold`、`keyword_threshold` 覆盖本次默认值；工具返回 `applied_settings` 供核对实际采用的范围和参数。保存冲突或结果不确定时，先刷新配置核对，不自动重试。

多库默认检索在同一个 stdio 操作中串行执行，失败或取消后停止后续库，不返回看似完整的部分批次。每次批次的内联正文合计最多约 12000 个 Unicode 字符，保留截断与续读偏移；仍需按文档 ID 核对原文。恢复默认值只修改编辑草稿，点击保存后才生效。范围、阈值和召回条数提高可控性，不保证检索相关性或替代原文核对。

## 让助手配置内置 WeKnora

首次设置选择工作目录后，可在“配置知识库”这一步体验对话配置；此步可跳过，配置对话中可点击“继续首次设置”返回。也可点击知识库页的“让助手配置 WeKnora”，或输入框加号 → 添加能力… → 配置 WeKnora。入口生成需求草稿，选择所有项目或当前项目，进入扩展助手后编辑并发送：

```text
帮我配置内置 WeKnora 知识库。
url：https://weknora.example.com/api/v1
key：你的 API Key
```

助手通过 `extensions_mcp_inventory` 读取脱敏配置与修订，再用 `extensions_weknora_configure` 保存。确认窗口显示 URL 和范围，不显示 Key；没有配置时创建内置预设，已有内置配置时更新 URL、Key 并启用，保留其他字段和其他 MCP。遇到其他范围的同名配置、同名服务指向其他程序、修订冲突或项目未信任时拒绝写入，不自动换范围或重复提交。

草稿不会自动发送或保存配置。用户选择在聊天中提供 Key 后，它会发送给所选模型并保存在原生对话及工具参数中；回复和工具结果不回显 Key。若希望避免凭据进入聊天，请使用 MCP 设置页的私密字段录入。

工具成功仅表示配置已保存、已启用，不表示连接成功。本轮结束后，在空闲会话重载资源或新建会话，再到知识库页连接服务并读取知识库。不在配置工具执行中重载自身，也不额外启动同一会话 worker。

## 浏览和聊天

- 独立页面支持知识库列表、文档分页、搜索结果、文档读取及继续读取。服务实际返回的 HTTP/HTTPS 来源链接可直接打开。资料以安全文本显示，包括原文中的 HTML 和 Markdown。
- 内置 0.7 返回的是未经重排的关键词／向量混合召回；检索可能触发上游 embedding。结果保留来源文档 ID、分块类型与截断提示，摘要和图片描述不能直接当作原文。阅读支持“下一页原文”与“继续读取此分块”；续读保持页范围和 Unicode 字符偏移，并保留同页其他分块。单分块累计展示达到约一百万 JS 字符后，可在聊天中按偏移继续。列表只包含 API Key 可访问的当前空间自有库；共享库 ID 可在聊天中明确提供，不会把名称猜作 ID。
- 知识库页只负责浏览与关键词检索，不提供提问输入或独立聊天。“前往助手对话”直接打开系统助手入口，无需先连接知识库或填写关键词，不携带问题草稿；提问和资料分析统一在系统对话输入框中完成。
- “引用到聊天”将所选片段、检索关键词、服务、知识库范围和实际工具名填入当前线程草稿，不把关键词转换成问题。进入对话后补充问题并点击发送，模型再使用原生 MCP 工具核对资料并回答。实际回答能力与引用质量取决于当前模型及服务返回内容。
- 已有聊天草稿或附件不会被覆盖，也不会自动发送消息。先保存或发送原草稿后再试。
- 页面读取不调用聊天模型，不建立另一份聊天、知识索引或文档数据库。页面结果不持久缓存；关闭或锁定后清除结果。明确引用到聊天并发送的内容会进入原生会话历史。

## 工具兼容与限制

| 操作 | WeKnora HTTP MCP | 内置 0.7 REST 桥接 | 旧版 MCP |
|---|---|---|---|
| 列出知识库 | `list_knowledge_bases` | 同名，`page/page_size` 分页 | `list_knowledge_bases` |
| 文档列表 | `list_documents {knowledge_base_id}` | `list_documents {kb_id}` | `list_knowledge {kb_id}` |
| 检索 | `search_knowledge {knowledge_base_ids}` | `search_knowledge {kb_id?}`，省略时使用已保存默认库；未保存则须指定单库 | `hybrid_search {kb_id}` |
| 文档读取 | `read_document {knowledge_id,offset,limit}` | `read_document {knowledge_id,page,page_size,content_offset}` | `get_knowledge` |
| 后续内容 | `next_offset` | 页级 `next_page`，分块级 `next_content_offset` | 服务提供 `list_chunks` 时可使用 |

工具以当前 worker 实际注册的目录与参数 schema 为准，只提供其中可用的操作。每次读取重新检查目录修订与原生可调用权限。页面没有上传、修改或删除知识的入口，不调用 WeKnora 的聊天／智能体工具；聊天中仍按用户实际授权和原生工具权限执行。

线程正在运行或设置正在保存时，等待结束后再读取。会话切换或连接恢复可触发新的知识库首屏加载，已有关键词检索、文档正文和失败请求不会自动重放；目录变化或读取失败后需手动核对。网络断开不代表服务器上的读取已经取消，执行槽持续保留到原生操作完成。读取返回预算为 320 KiB；超出时缩小范围或在聊天中分段读取。

验证使用独立身份、本地合成 MCP 与合成模型，覆盖真实 HTTP、唯一受管 worker、Pi 原生连接、工具权限钩子与原生会话持久化；不等同于用户实际 WeKnora 部署、凭据与数据的联调验收。

接口见 [API](API.md#知识库读取)，实现位置见[模块导航](development/MODULES.md)。WeKnora 工具参考：[内置端点](https://github.com/Tencent/WeKnora/blob/main/internal/mcpserver/tools_retrieve.go)与[旧版 MCP](https://github.com/Tencent/WeKnora/tree/main/mcp-server)。

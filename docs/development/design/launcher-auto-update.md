# 启动器整包自动升级设计讨论

状态：13 项设计选择均已确认，完整方案待最终核对；尚未实现、部署或发布。本文记录后续实现目标，不代表当前升级器已经具备这些能力。当前行为见[版本与更新](../../UPDATES.md)和[桌面启动器](../../DESKTOP_LAUNCHER.md)。术语见[项目术语](../../../GLOSSARY.md)。

后续接手从[启动器整包升级 Wayfinder](../LAUNCHER_UPDATE_WAYFINDER.md)进入，按职责定位现有实现、阶段依赖、待补机制与验证入口；产品选择仍以本文为准。

## 已确认的产品边界

用户于 2026-10-19 确认第一轮三项推荐：

1. 启动器、托盘、后台服务及配套运行环境作为一个发布版本整体升级、整体回退；成功须同时核对启动器与服务版本。
2. 用户确认更新后，先下载与预校验，再正常停机并退出旧托盘，切换后自动重新打开新版启动器。遇到未结束任务或无法确认退出，停止切换并显示原因，不强制杀进程；用户无需重新寻找目录或修改快捷方式。
3. 新版首次启动处于启用前验证阶段，暂不接受业务操作。启动器控制通道、服务就绪、版本与必要数据读取通过后才开放使用。验证失败时，确认新版已退出后恢复旧程序与升级前数据；无法确认退出或恢复失败时保留现场，停止自动操作。

用户随后确认第二轮三项推荐：

4. 采用固定入口、独立版本目录与退出后更新助手。新包在独立目录准备，旧服务和托盘正常退出后，由助手复核文件并切换版本，再自动启动。保留旧版目录用于回退；快捷方式保持有效，数据与配置使用原路径。固定入口自身需要升级时，也由助手在其释放后替换。
5. 引入发布清单数字签名，启动端内置验证公钥，发包增加签名步骤，私钥独立保管。SHA256、逐文件清单与激活前复核继续保留。签名用于核验授权发布者，不以 Windows 代码签名证书作为实现前提。
6. 对不支持新协议的旧安装，允许用户首次额外运行一次迁移助手，之后使用一键整包升级。迁移须识别原安装、正常停机、备份并安装新入口，保留原数据与快捷方式，支持失败恢复；准确 1.7.3 发布包的迁移路径尚待验证。

用户随后确认第三轮四项推荐：

7. 下次打开固定入口先检查同一次未完成升级的持久化记录、实际文件、退出证明与备份。已提交则启动新版；未提交且具备可靠恢复条件则回退旧版；步骤结果不明则显示恢复界面并保留现场。自动回退只尝试一次，失败后停止，不反复启动与恢复。
8. 新版启用前验证默认最多 120 秒，服务就绪后至少稳定观察 15 秒，时限可配置。检查启动器控制通道、组件版本、服务就绪、必要数据读取和托盘状态，全程展示进度；到期未通过进入失败处理，回退前仍须确认新版正常退出。不得向真实会话发送测试消息。
9. 验证通过并开放业务操作后，不自动恢复升级前数据。此后故障保留最新数据并提供诊断与人工恢复入口；主动回退另走维护流程，先保存当前数据，再判断旧版兼容性。
10. 首期由维护者独立保管加密签名私钥，发布时在本机显式签名。私钥不进入源码、发行包或更新仓库；构建与签名分开，正式发布前必须签名，客户端拒绝无签名或签名无效的更新。正常换钥由现有受信任密钥授权；私钥丢失或泄露经独立可信渠道人工恢复，不从更新清单直接接受陌生公钥。

用户于 2026-10-20 确认第四轮三项推荐：

11. 随包提供独立的“修复启动器”入口，主 EXE 替换失败或无法打开时仍可检查升级记录，在条件可靠时恢复旧入口。修复工具及必要依赖单独保留，不依赖正在被替换的组件，不绕过签名与文件校验。
12. 保留 schemaVersion:1 清单并增加签名字段，新启动器强制验签。先准备签名清单再推广新启动器；无签名源明确拒绝，不降级放行。首个受信任公钥随维护者通过独立可信渠道交付的迁移工具或整包内置，不从更新清单临时获取并信任。旧客户端仍只有原有校验能力。
13. 首次迁移无法确认旧版安全退出时，迁移助手暂停并提示进入独立维护流程；不能只凭窗口关闭或 PID 消失开始恢复数据或替换程序。实施时用本地准确 1.7.3 归档做隔离迁移测试，完成迁移后再使用新机制的一键整包升级。

## 完整升级流程

以下为已选边界的流程汇总，不是已经执行的操作：

1. 固定入口检查上次升级记录；存在未完成操作时，先核对同一事务，不直接再次提交更新。
2. 用户确认目标版本后锁定本次目标与包身份，校验清单签名，下载并校验 ZIP 字节数、SHA256、安全解压路径、逐文件清单及组件版本，在独立目录准备候选。
3. 核对全局空闲并关闭新工作准入，正常停止服务，取得可信清理完成证明，完成停机备份并保存交接记录；备份不完整不得进入激活。
4. 完整退出旧托盘与外层启动器。独立助手确认准确进程已退出并接管同一安装互斥，再复核原件、候选和交接状态；发现变化或结果未知时停止。
5. 激活完整的新版本，必要时替换已释放的固定入口；保留可恢复的旧版本、原入口与事务记录。原安装身份、数据路径和快捷方式继续有效。
6. 自动启动新版，进入启用前验证。默认总时限 120 秒，服务就绪后至少稳定观察 15 秒；期限内无法完成全部检查即视为未通过，超时不等于进程已退出。
7. 验证通过后先持久保存成功提交记录，再开放业务准入。失败则先确认新版正常退出，保留失败现场的数据快照，核验并恢复升级前备份和整套旧组件，最多进行一次自动回退。
8. 退出不明、备份异常、恢复中断或回退失败时，停止自动操作并显示诊断。固定入口不可用时通过独立修复入口处理；已开放业务后不得自动恢复升级前数据。

关键状态为：准备候选、等待停机、备份完成、等待外层退出、激活中、启用前验证、成功提交、回退中、已回退、需人工恢复。状态记录须绑定同一安装、操作、目标包和恢复点；状态名本身不代替文件及进程事实核验。

## 代码事实与现有边界

- [原生 EXE](../../../native/pivane-desktop-launcher.cs) 从自身目录启动托盘并退出；[托盘脚本](../../../scripts/desktop-tray.ps1) 仍加载原根 EXE 程序集，并从原根启动 runner。EXE 主进程退出不等于组件已释放。
- [受管启动器](../../../server/pi-managed-launcher.js) 只从候选目录启动服务，切换 active/previous，未激活候选包的外层启动器。仅把新版 EXE 放进候选包不会使旧入口自动更新。
- [安装锁](../../../server/pi-installation-lock.js) 与安装根关联；数据默认路径、桌面安装身份也依赖安装根。不能直接把候选目录当成另一套独立安装启动。
- [便携包安装器](../../../server/pi-portable-installer.js) 已校验 ZIP 字节数、SHA256、解压清单及逐文件哈希，并保护本地未发布源码。尚未覆盖退出后的外层激活事务；下载时校验不能替代激活前复核。
- 现有服务停机要求可信清理完成证明；退出超时或只有 PID 消失不代表可以恢复数据和启动其他所有者。
- 已只读核验本地 `dist/baizelingtai-1.7.3.zip`：326606675 字节，SHA256 `ec39ded0df23667e58800773b86db1a80bae7e032a1e85b894b3bd4b5fc341d9`，与同名校验文件一致，包内应用版本为 1.7.3。该包只切换候选服务，且没有当前桌面模式要求的可信清理完成证明；不能假定本地归档等同于用户实际部署包，也尚未进行迁移执行验证。
- 本地 1.7.3 包与当前源码的清单解析均接受 `schemaVersion:1` 的额外字段；新增签名字段不会使旧解析器拒绝清单，但旧解析器会忽略它，不能据此声称旧版已获得签名验证能力。修改为 schemaVersion:2 会被旧解析器拒绝。具体签名载荷与新客户端协议尚待实现和测试。

## 已确认边界对实现的要求

- 安装身份、数据路径和安装锁始终绑定原安装，不随程序版本目录变化；独立助手在交接期间也必须遵守同一安装互斥。
- 启用前验证期间同时阻止普通 API、WebSocket 与预约等后台入口产生业务工作；服务就绪不单独构成升级成功。
- 验证通过后，先持久保存成功提交记录，再开放业务操作。之后启动失败不得回到升级前数据，防止提交记录与实际业务准入之间的中断触发错误回退。
- 退出后的助手重新核验候选文件、准确目标与原件身份；停机、助手交接、入口替换与恢复步骤均记录在同一升级事务中。超时、进程消失或记录缺失不替代清理证明，也不自动重放结果未知的变更。
- 保留现有源码未发布改动保护、原生备份范围、权限和保留策略；这些保护不因启动器整包升级而放宽。

## 后续实现与验收范围

首批实现按本次讨论的 Windows x64 便携版桌面链路组织，不据此承诺其他平台能力。继承原有安装、数据、停机及原生身份边界；实际验证遵循开发验证矩阵，桌面验证使用独立合成身份，不操作真实会话。

| 验证场景 | 应达到的结果 |
|---|---|
| 正常整包更新、退出后再双击原快捷方式 | 启动器、托盘、服务与配套环境使用同一目标版本，安装身份和数据原路径保持一致 |
| 无签名、签名无效、陌生公钥、ZIP 或解压后文件被修改 | 拒绝激活，保留旧版与诊断；激活前复核能发现准备后发生的变化 |
| 任务未结束、清理证明缺失、托盘未退出、文件被占用 | 不强制终止或覆盖，不启动竞争所有者，不恢复数据 |
| 新版就绪失败、版本不匹配或验证超时 | 不开放业务；确认退出并核验恢复条件后最多自动回退一次 |
| 新版验证中写入数据后失败 | 恢复前保存失败数据现场，再恢复经核验的停机备份；不会漏回退外层组件 |
| 助手交接、入口替换、提交或恢复阶段中断 | 下次检查同一次事务；只有可证明的状态才能继续处理，未知结果保留现场，不自动重放 |
| 固定入口不可用 | 独立修复工具及其必要依赖仍能工作，且遵守相同锁、签名和恢复核验 |
| 已提交并开放业务后故障 | 保留最新业务数据，不自动倒回升级前备份 |
| 本地准确 1.7.3 归档迁移、旧父启动器运行新候选服务 | 识别外层与服务版本差异；缺少可信停机证明时转独立维护，不宣称直接全自动迁移已通过 |
| schemaVersion:1 增加签名字段、新客户端面对旧无签名源 | 旧解析器仍能读取原字段；新客户端严格验签并明确拒绝无签名源 |

具体签名编码、协议字段、持久化与原子替换实现须在后续编码中确定并验证，不得削弱已确认边界。密钥生成、真实迁移、构建交付、部署和发布均尚未执行；设计确认不等同于这些操作已经完成。

本讨论只记录设计，不修改升级实现，不重启真实服务。当前无剩余产品选择问题，待用户核对完整流程、确认共享理解后结束设计讨论；实施按后续任务授权进行。

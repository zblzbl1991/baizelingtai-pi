# 人员调配：需求与设计讨论

状态：已进入源码实施，功能开发中。本文不表示功能已完成、已部署或已发布。

本文记录已确认的业务要求和待确认的设计建议。术语见 [人员调配术语](../../../GLOSSARY.md)。不保存真实人员清单、个人信息、共享文件链接或运行实例资料。

## 已确认的业务要求

1. 项目负责人提出用人需求，调配负责人统一选择和确认人员。
2. 默认只使用本事业部人员。跨事业部借人须由调配负责人明确允许，许可只对当前选人方案有效，下一次选人恢复本事业部默认范围。
3. 第一版按事业部、日期和直签要求筛选，不增加岗位、技能或证书筛选。
4. 日期按天计算，包含开始日和结束日。默认不另加准备或转场时间。
5. 默认同一批人员全程参与，中途换人作为特殊情况处理。
6. 预占和正式安排均计入占用。请假、培训等不可用时间也须登记并排除。
7. 所需人数是最低人数要求，允许超额安排。
8. 项目期间每天均须达到最低人数，并至少有一名直签人员覆盖。
9. 直签人员指与本公司直接签订劳动合同的人员；标记由调配负责人维护。
10. 允许部分预占，持续显示人数和直签缺口，满足全部条件后才标记安排达标。
11. 改期、延长或换人前检查新安排。未经调配负责人确认保留原安排。
12. 预占不设自动失效期限，占用只影响登记的日期范围。
13. 项目取消、撤回人员或提前结束后，由调配负责人确认释放对应未发生的占用，保留历史。
14. 提供可用人员、项目安排和人员占用三个视图。
15. 需要支持将 Excel 文件保存在成果中心。
16. 用户先完成需求讨论，随后调用 implement-spec 并确认测试入口与实施任务图，授权进入源码实施；未授权真实台账操作、部署或发布。

## 已核对的现有能力

- [成果中心](../../ARTIFACTS.md) 支持独立保存不可变文件副本；没有原位编辑 Excel 的接口。
- [办公附件](../../COMPOSER_TOOLS.md) 支持 Excel 附件读取；当前解析器不重算公式，也不直接转换日期格式。
- [助手档案](../../AGENT_PROFILES.md) 支持角色说明和技能设置；档案不构成用户权限隔离。
- [原生设置](../../NATIVE_SETTINGS.md) 支持 Pi 包及其中的技能、扩展等资源。完整业务网页仍需在应用源码中接入。
- [访问控制](../../ACCESS_CONTROL.md) 使用单实例共享权限，尚未提供负责人各自登录的账户隔离。

以上为源码能力依据，不代表当前运行实例已核验。

## 已确认的产品决定

- 当前调配记录以模块台账为准，Excel 用于导出成果。数据归属决定见 [ADR-0001](../../adr/0001-staffing-ledger-authority.md)。具体存储技术尚未选定。
- 日常操作以聊天为主。智能体展示候选人员和安排卡片；三个视图用于核查并允许手动调整。
- 人员调配随工作台内置，作为可选能力启用后才能使用。
- 使用专用人员调配智能体作为聊天入口。
- 智能体先推荐一组满足人数和直签要求的完整名单，由调配负责人调整并确认。推荐方案不产生人员占用；人员不足时沿用缺口展示和部分预占规则，不虚构完整可用名单。
- 通过聊天中的具体安排卡片确认预占、正式安排和调整。卡片列出人员、日期、人数和直签情况。
- 在满足事业部、日期和直签条件后，按用人开始日前 90 天内已登记项目占用天数从少到多推荐，调配负责人可以替换推荐人员。历史不足时仍可推荐，须明确显示“按已录入记录排序，历史不完整”；当前和已知未来占用仍须核对。
- 首次启用须录入人员、当前和已知未来的项目、预占、请假及培训，由调配负责人核对初始台账后才能正式调配。缺少占用记录不等于已核实空闲。
- 停用人员调配能力时关闭功能入口和工具，保留台账、变更历史和已保存成果；再次启用继续使用原有数据。
- 已安排人员临时请假时，先如实登记请假，再重新检查对应日期的人数和直签覆盖。标记受影响项目的缺口，由调配负责人安排替补，保留原安排历史，不自动调动其他项目人员。
- 首次启用使用引导流程，依次创建专用人员调配智能体、配置配套 Skill 和工具、导入人员及占用记录，最后由调配负责人核对初始台账。再次启用沿用已有配置和数据，不重复创建。
- Excel 按需导出。调配负责人通过聊天请求或“导出并保存到成果”操作生成文件并保存到成果中心，文件标明生成时间和台账版本。日常调整保存到台账，不自动为每次调整生成 Excel。

## 已纳入实施规格的方案

以下方案已纳入本次实现规格。具体交付状态以集成分支代码和验证结果为准：

- 页面和聊天共用一个调配模块。
- 专用智能体配备一个主 Skill 和一个随包提供的 Pi 工具包；其他新建对话在资源发现和工具注册前排除人员调配上下文。
- 统一模块负责冲突、人数、直签和变更检查；Skill 负责工作步骤，插件负责调用工具。
- 提交时核对最新台账，避免两个聊天同时占用同一人员。
- Excel 导入先展示差异；旧文件不得直接覆盖最新安排。

## 职责方案

| 部分 | 职责 |
|---|---|
| 功能页面 | 提供可用人员、项目安排、人员占用三个视图，支持人工核查和调整 |
| 专用智能体 | 理解需求、查询最新台账、展示推荐方案、解释缺口 |
| 主 Skill | 规定信息收集、查询、推荐、确认及结果核对的工作步骤 |
| 随包提供的 Pi 工具包 | 为专用智能体提供查询、准备变更、导入检查、导出及操作结果查询工具 |
| 调配模块 | 统一执行冲突、人数、直签与变更检查，保存台账和历史 |
| 成果中心 | 独立保存按需导出的 Excel 版本 |

# 人员调配：需求与设计讨论

状态：既有人员调配能力已有源码实现；2026-10-23 管理界面改版的业务设计已整体确认，进入实施前技术路线决策，尚未进入本轮源码实施。部署与发布状态另行核对。

本文记录已确认的业务要求和待确认的设计建议。术语见 [人员调配术语](../../../GLOSSARY.md)。不保存真实人员清单、个人信息、共享文件链接或运行实例资料。

## 已确认的业务要求

1. 项目负责人提出用人需求，调配负责人统一选择和确认人员。
2. 默认只使用本事业部人员。跨事业部借人须由调配负责人明确允许，许可只对当前选人方案有效，下一次选人恢复本事业部默认范围。
3. 第一版按事业部、日期和直签要求筛选，不增加岗位、技能或证书筛选。
4. 日期按天计算，包含开始日和结束日。默认不另加准备或转场时间。
5. 默认同一批人员全程参与，中途换人作为特殊情况处理。
6. 预占和正式安排均计入占用。请假、培训等不可用时间也须登记并排除。
7. 所需人数是最低人数要求，允许超额安排。
8. 项目期间每天均须达到最低人数，并至少有一名直签人员覆盖。
9. 直签人员指与本公司直接签订劳动合同的人员；标记由调配负责人维护。
10. 允许部分预占，持续显示人数和直签缺口，满足全部条件后才标记安排达标。
11. 改期、延长或换人前检查新安排。未经调配负责人确认保留原安排。
12. 预占不设自动失效期限，占用只影响登记的日期范围。
13. 项目取消、撤回人员或提前结束后，由调配负责人确认释放对应未发生的占用，保留历史。
14. 提供可用人员、项目安排和人员占用三个视图。
15. 需要支持将 Excel 文件保存在成果中心。
16. 用户先完成需求讨论，随后调用 implement-spec 并确认测试入口与实施任务图，授权进入源码实施；未授权真实台账操作、部署或发布。

- [办公附件](../../COMPOSER_TOOLS.md) 支持 Excel 附件读取；当前解析器不重算公式，也不直接转换日期格式。

## 已确认的产品决定

- 当前调配记录以模块台账为准，Excel 用于导出成果。数据归属决定见 [ADR-0001](../../adr/0001-staffing-ledger-authority.md)。既有源码使用身份私有 JSON 台账，本轮属性生效记录的数据结构由后续实施规格确定。
- 管理界面优先呈现人员、项目和日期占用，支持独立完成人工调配；专用智能体承载自然语言分析、推荐和方案准备。2026-10-23 用户确认以此替代原“日常操作以聊天为主”的界面方向；改版设计与实施状态见下节。
- 人员调配随工作台内置，作为可选能力启用后才能使用。
- 使用专用人员调配智能体作为聊天入口。
- 智能体先推荐一组满足人数和直签要求的完整名单，由调配负责人调整并确认。推荐方案不产生人员占用；人员不足时沿用缺口展示和部分预占规则，不虚构完整可用名单。
- 通过聊天中的具体安排卡片确认预占、正式安排和调整。卡片列出人员、日期、人数和直签情况。
- 在满足事业部、日期和直签条件后，按用人开始日前 90 天内已登记项目占用天数从少到多推荐，调配负责人可以替换推荐人员。历史不足时仍可推荐，须明确显示“按已录入记录排序，历史不完整”；当前和已知未来占用仍须核对。
- 首次启用须录入人员、当前和已知未来的项目、预占、请假及培训，由调配负责人核对初始台账后才能正式调配。缺少占用记录不等于已核实空闲。
- 停用人员调配能力时关闭功能入口和工具，保留台账、变更历史和已保存成果；再次启用继续使用原有数据。
- 已安排人员临时请假时，先如实登记请假，再重新检查对应日期的人数和直签覆盖。标记受影响项目的缺口，由调配负责人安排替补，保留原安排历史，不自动调动其他项目人员。
- 首次启用使用引导流程，依次创建专用人员调配智能体、配置配套 Skill 和工具、导入人员及占用记录，最后由调配负责人核对初始台账。再次启用沿用已有配置和数据，不重复创建。
- Excel 按需导出。调配负责人通过聊天请求或“导出并保存到成果”操作生成文件并保存到成果中心，文件标明生成时间和台账版本。日常调整保存到台账，不自动为每次调整生成 Excel。

## 2026-10-23 管理界面改版讨论

状态：21 项设计决定及整体共享理解已于 2026-10-23 经用户确认；以下尚未接入正式界面，不代表旧功能或原型已经完成本轮改造。原型视觉沿用项目品牌、侧栏、主题变量和控件规范。

- 人员资料支持页面单条新增、编辑，字段沿用人员编号、姓名、事业部和是否直签。编号保存前校验并预览确认，保存后只读；本轮不提供人员改号迁移，确需改号另设专项，不通过重复建立同一人员代替纠错。事业部、直签真实变化按生效日期保留此前状态，生效前日期沿用当时属性；姓名纠错直接更新并保留修改历史。时间语义见 [ADR-0004](../../adr/0004-staffing-effective-dated-person-properties.md)。
- 负责人已明确人员和日期时，可在管理页直接选人、检查并确认。页面保留完整人工调配路径，与助手方案使用同一套台账检查和确认机制。管理页支持独立新增业务项目及用人需求，填写编号、名称、负责人、事业部、起止日期和最低人数；保存项目不自动占人，后续可人工选人或交给调配助手准备方案。
- 业务项目编号创建后只读；名称、负责人允许编辑并留痕。未开始项目的事业部、最低人数和起止日期可在检查影响后修改；已开始项目沿用补人、换人、延长、提前结束、撤回等明确调整，不任意重写原用人要求，保留已发生安排。
- 点击调配助手直接进入台账绑定的专用助手对话，携带当前人员或业务项目、日期及任务作为待发送草稿，由用户发送后开始工作。从人员或业务项目发起具体任务时默认新建专用会话，保留主动继续已有会话的入口；仅打开调配助手浏览时进入最近专用会话，没有历史时新建。主动继续已有会话而该会话有文字或附件时，保留原草稿，新任务单独显示为待带入任务，不自动拼接；提供新建专用会话承接，也允许用户处理原草稿后主动带入。
- 助手绑定失效或专用助手停用时，管理页继续正常可用，提示修复绑定，不自动切换到其他助手。主动选择的目标会话正在工作时，保留待带入任务，可新建会话或稍后处理，不自动发送；同一助手的其他会话正在工作不等于所有新会话均不可用。
- 专用会话归入选定的人员调配助手分类及固定服务器工作目录，首次配置时选择现有目录，已有有效绑定可以沿用。业务项目只作为任务内容，不自动为每个业务项目创建磁盘目录或迁移旧会话。
- 本轮纳入人员停用及恢复，两者指定生效日期，默认今天。人员在停用期间不得加入新的推荐与安排，保留资料、既有安排、占用和历史；该期间不计入项目有效覆盖，人数及直签缺口列为待处理项，由负责人撤回或换人，不自动释放。恢复后重新参与调配，但不复活已经释放的安排；不提供彻底删除人员。
- 人员转事业部后，既有已预占及正式安排继续有效，不因转部自动撤销。新方案按整个用人期间的归属检查；期间涉及跨事业部时须明确允许借人，或由负责人分段准备安排，不自动拆分或放宽许可。
- 聊天安排方案在同一卡片中核对、调整名单、重新检查并选择预占或正式确认，不再追加普通二次确认窗口。名单变化后必须重新检查；提交结果不确定时保留原操作卡片，查询原操作结果，不重复提交。
- 卡片生成后台账发生变化，保留旧名单用于对比，暂停直接确认；用户重新检查原选择后，展示失效人员、新缺口及调整结果，再由用户确认，不自动换人或提交。
- 日常界面使用人员台账、项目安排、排期日历和变更记录四个视图，默认人员台账；人员可用情况默认查询今天，日历默认本周，日期范围可调整。打开详情再返回保留筛选和列表位置。初始化流程只在首次启用或尚未核对完成时展示，数据导入导出收进数据管理。
- 旧台账以已登记的当前属性建立升级基线，明确此前真实生效日期未知；后续属性变化按明确日期记录。历史属性无法证实时标明未核实，不把保存时间、导出时间或最早项目日期当作业务生效日期，也不将证据不足的历史显示为已核实达标。原项目历史完整性声明不能代替人员属性历史证明。
- 新版 Excel 保留人员状态及属性生效记录，继续提供旧版差异导入。旧版文件改变已有人员属性时须明确生效日期、预览差异后确认；缺少新字段不清除既有历史或恢复停用人员。已保存的旧报告维持原字节和版本。
- 普通人员属性变更选择今天或未来日期。过去日期的更正使用独立历史纠错流程，明确日期范围、原因及受影响项目，预览后确认；保留变更前后记录，需要更新报告时生成新版本，不覆盖旧成果。
- 既有台账事实来源、占用检查、跨事业部许可与人工确认规则沿用。当前代码仅按专用助手身份跳转，尚无完整的“选择会话并安全交接任务草稿”入口；人员单条维护也需补充接口，不能用原型按钮代替实现状态。

新增设计决定沿用本节维护；本地访谈进度见 11 票，不另建一份公开规格。

## 已纳入原实施规格的方案

以下方案已纳入本次实现规格。具体交付状态以集成分支代码和验证结果为准：

- 页面和聊天共用一个调配模块。
- 专用智能体配备一个主 Skill 和一个随包提供的 Pi 工具包；其他新建对话在资源发现和工具注册前排除人员调配上下文。
- 统一模块负责冲突、人数、直签和变更检查；Skill 负责工作步骤，插件负责调用工具。
- 提交时核对最新台账，避免两个聊天同时占用同一人员。
- Excel 导入先展示差异；旧文件不得直接覆盖最新安排。

## 职责方案

| 部分 | 职责 |
|---|---|
| 功能页面 | 提供可用人员、项目安排、人员占用三个视图，支持人工核查和调整 |
| 专用智能体 | 理解需求、查询最新台账、展示推荐方案、解释缺口 |
| 主 Skill | 规定信息收集、查询、推荐、确认及结果核对的工作步骤 |
| 随包提供的 Pi 工具包 | 为专用智能体提供查询、准备变更、导入检查、导出及操作结果查询工具 |
| 调配模块 | 统一执行冲突、人数、直签与变更检查，保存台账和历史 |
| 成果中心 | 独立保存按需导出的 Excel 版本 |

原实施轮曾确认调配公开模块与 HTTP、受管会话实际模型输入、Chromium 桌面与手机三个测试层面，以及六张实施票的任务图，当时使用独立集成分支。本轮管理界面改版尚未拆分实施任务；验证按当前开发流程及本机约定选择，不能将旧结果当作改版已验收。

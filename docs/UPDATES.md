# 版本与更新

未配置内网更新源时，白泽灵台应用的外网更新源为 [zblzbl1991/baizelingtai-pi Releases](https://github.com/zblzbl1991/baizelingtai-pi/releases)，版本检查、发布链接及应用归档下载使用同一仓库。配置内网源后只检查内网清单；访问失败显示检查失败，不回退外网。

“设置 → 版本与更新”优先展示白泽灵台的**当前版本、最新版本**及状态；当前实际运行的 Pi Coding Agent 版本放在默认折叠的“引擎与依赖”中，检查期间保留展开状态。首次打开且没有缓存时自动检查一次，也可点击“检查更新”；部署端查询 GitHub Releases 和 npm，结果缓存 5 分钟。白泽灵台默认从公开 Release 中选取 SemVer 最高版本，**包含预发布版**，页面不再区分渠道。网络不可达时会分别显示检查失败，不推断已经是最新。

“自动检查底层引擎更新”默认开启：页面可见时最多每 24 小时查询一次 npm 正式版；发现新版显示“底层引擎有可用更新”，空闲时的轻量提醒可打开版本页、延后或忽略当前版本。引擎提醒不表示白泽灵台应用有新版。检查和提醒都**不会下载或安装**。工作台的 Pi 依赖与机器上全局 Pi CLI、Packages 扩展是不同安装。

## GitLab 与内网 Windows 更新源

Windows 便携版可通过 `npm run pack:windows` 自动读取本机 `.baizelingtai-update-build.json` 并内置公开 GitLab/内网清单地址，见[便携版构建参数](DESKTOP_LAUNCHER.md#内网更新源与-gitlab-分发)。已有实例也可通过 `BAIZELINGTAI_UPDATE_FEED_URL` 指定完整 HTTP(S) 清单地址，安全重启后生效。显式空值恢复默认 GitHub/npm 检查；不设置则沿用包内 `baizelingtai-portable.json` 的 `updateFeedUrl`，没有包内配置时沿用官方源。旧 `PIVANE_UPDATE_FEED_URL` 和 `pivane-portable.json` 保留读取兼容；新环境变量优先，两个元数据文件同时存在时拒绝猜测，不改写或迁移用户数据。URL 不允许账号密码、片段或凭据查询参数；GitLab API 形式仅支持 `ref` 查询参数。当前支持无需登录的公开清单与下载地址，浏览器登录态不会转交服务器。

配置清单后，打开更新页和“检查更新”只查询该清单，不访问 GitHub/npm，也不在失败时回退外网。保留 5 分钟缓存、12 秒请求超时与并发合并；内网失败明确显示检查失败。此模式不进行后台 npm 自动检查，也不显示 Pi 上游提醒。版本页展示该源的发布版本、配套 Pi 版本、Windows ZIP 下载入口及 SHA256；这不表示外网最新版，也不核对本地未发布的源码修改。首次打开没有检查记录时自动查询一次，后续由“检查更新”触发。

可同时设置 `BAIZELINGTAI_UPDATE_RELEASES_URL` 为与清单同源的 GitLab 发布页面（例如项目的 `/-/releases`）。未检查、检查失败、暂无适用版本，或清单省略 `releasesUrl` 时，发布入口仍指向该页面；清单提供的有效 `releasesUrl` 优先。该配置仅在内网清单模式生效，遵循相同的 URL 安全限制，安全重启后生效，不改变检查地址。

清单 `schemaVersion:1` 包含 `version`、`piVersion`、`platform:"win32"`、`arch:"x64"`、`channel:"stable"或"preview"`、ISO `publishedAt`、`package`、小写 64 位 `sha256`、正整数 `bytes` 和可选 `releasesUrl`。版本必须为 SemVer；stable 不允许预发布应用版本。`package` 可为相对清单地址的 ZIP 路径或同源完整地址，发布页也须同源；不接受跨域、凭据 URL 或其他安装包格式。其他平台/架构或 stable 查询遇到 preview 清单显示暂无适用发布。当前清单只描述一个候选包，stable/preview 同时分发可使用各自清单地址。

推荐在公开 GitLab 项目保存 `updates/latest.json`，大 ZIP 放在该项目的 Generic Package Registry，或与清单一起放在仓库/内网静态站点。先上传验收通过的准确 ZIP，再发布其清单；不要只上传清单而把下载地址留在外网。同版本正式包不覆盖，版本号不变的重新构建不会提示升级。GitLab 项目的公开可见性不保证 Package Registry 已允许匿名下载，发布前须从用户网络确认清单和 ZIP 均无需登录。

`npm run pack:windows` 的外层 `-offline.zip` 解压后提供应用 ZIP、同名 `.sha256` 和 `updates/latest.json`。将清单按该路径提交到内网 GitLab 仓库，将应用 ZIP 上传到清单 `package` 指定的 Generic Package Registry 地址；两处都就绪后自动检测和下载才可用。外层 ZIP 用于搬运，更新器下载内部应用 ZIP。

支持此功能的 Windows x64 便携版，通过受管启动器启动并配置内网清单后，发现新版会显示“一键更新”。点击后服务器重新核对目标，页面展示版本与 SHA256；确认已保存草稿、结束任务、暂停预约并停止同一数据的外部 Pi 进程，再点击“确认并更新”。服务器再次检查全局空闲，锁定普通 API/WS 新工作，下载并校验完整 ZIP、安全解压路径与逐文件清单，以独立身份验证候选程序，然后正常停止旧服务、备份原路径数据并启动新版。页面只查询进度，切换断线不会重新提交；成功后刷新当前版本。关闭页面不取消已接受操作。

下载和安装失败保留旧服务；新版启动失败时先等待其退出，保留失败后的数据快照，再恢复本次停机备份并启动旧程序。恢复失败禁止启动，须在独立维护窗口处理。原程序、候选、准确 ZIP 和备份保存在原安装目录 `.pivane-runtime` 中；继续使用原来的桌面或 `npm start` 入口，受管指针选择已更新程序。身份、媒体、配置、预约文件和更新源固定为原绝对路径，`.env` 与项目文件不被候选覆盖。清单变化、源码清单中的本机未发布修改、字节数/哈希不符、重定向或下载失败都会停止，不自动重试。

Windows 手动托盘要求服务支持可信的清理完成证明。当前服务或失败候选未提供证明时，即使退出码为 0 也保持未知，保留运行锁并禁止启动另一个所有者；维护流程不会在这种状态下自动恢复数据或重新启动，需按诊断信息在独立维护窗口处理。只查询同一次操作，不重发提交。具体边界见[托盘启动器](DESKTOP_LAUNCHER.md)。

自动更新只适用于带新更新器的 Windows 便携版与公开同源 ZIP；其他平台、旧启动器或 direct 模式仍由浏览器下载，在独立维护窗口更新。现有 tar.gz/npm 安装器不处理 ZIP；内网源的独立 Pi `update` review 仍拒绝。旧包不会因清单或环境变量变化自动获得一键更新能力。便携版默认 `data` 位于原解压目录，不应移动或覆盖原用户数据。

更新页不展示“网络代理设置”入口。后端版本检查沿用服务器的网络配置，内网清单须从部署机器可访问；点击发布页和下载链接使用浏览器网络，独立 Agent 的下载命令使用其自身运行环境。代理覆盖范围见[网络与访问](ACCESS_CONTROL.md#代理覆盖范围)。

## 请独立 Agent 协助

更新页暂时隐藏“交给独立 Agent 协助更新”区域及提示词复制入口。需要人工维护时，可直接请**部署机器上独立运行**的 Agent 或管理员按本指南操作。有新版时先确认目标，已有授权无需重复确认；更新前确认空闲、暂停预约、保存草稿，正常停机备份并保留旧程序。

维护时以本机配置和页面显示的更新来源为准；若采用 GitLab 内网源而页面来源不符，先核对配置与实际运行版本，再继续维护。

不支持内网源的旧包不会因新增环境变量自动获得该能力。首次由部署机器上的独立 Agent 或管理员按内网清单下载并校验新整包，完成备份与切换；新版启动后再确认页面的 `source` 为内网清单、版本检查使用该源。

内网 Windows 维护以清单地址为入口，不使用页面缓存的版本、下载地址或哈希。Agent 重新读取 `latest.json`，按 SemVer 比较 `version` 与实际运行版本；相同或更旧则结束，有新版才按 `package` 下载同源 ZIP，核对 `bytes` 和 `sha256`。清单检查失败时停止并核对，不跳过清单或校验。整包更新不单独升级 Pi 或运行 npm 安装，保留本机未发布的修复、旧程序、实际数据绝对路径、权限、`.env` 和更新源配置；启动后验收版本与数据，失败回退。

具体安装步骤按本指南和[安装与恢复](INSTALL_RECOVERY.md)执行：固定已确认的清单字段，遇到登录页、重定向、下载失败、目标变化、字节数或哈希不符时停止，不自动重试；解压前检查 ZIP 路径。常规更新校验完整 ZIP 的字节数和 SHA256，然后核对新程序版本与启动状态，不逐文件对比依赖；维护者发包前的准确包验收仍核对 `PORTABLE_MANIFEST.json`。新程序首次启动前将原来随旧目录解析的数据默认值固定到原来的绝对路径，包括 `PI_CODING_AGENT_DIR`、`PI_MEDIA_DATA_DIR`、`PI_MEDIA_CONFIG_DIR` 和 `PI_WEB_DEFERRED_FILE`，不能仅复制 `.env` 就假定默认路径相同。同一身份先停旧实例再启新实例；回退先停新实例再恢复原路径数据和旧程序。隔离模拟入口见[Windows 内网更新演练](DESKTOP_LAUNCHER.md#隔离模拟-gitlab-更新)。

不要让运行在待更新白泽灵台实例中的 Agent 停止或重启承载它当前会话的服务。默认版本卡片暂时隐藏“白泽灵台发布页面”GitHub 链接；内网 Windows 卡片保留更新来源、ZIP 下载入口和校验值。支持上述 Windows 整包一键更新的实例由独立受管启动器执行安装、备份与切换，其余实例使用独立维护流程。实际安装、备份与恢复可参考[安装与恢复](INSTALL_RECOVERY.md)、[macOS](MACOS.md)及[Windows](WINDOWS.md)；先根据部署环境和目标版本核对步骤，不盲目套用旧版本命令。

## 锁定的 Pi 适配版本

白泽灵台与经适配的 Pi 版本成组安装，版本约束取自发布包的 `package.json`。绑定版拒绝独立升级 Pi；应用、原生 MCP 和子任务适配须一起验证更新。版本检查展示上游版本，不表示可以直接安装。各版依赖见[发布说明](README.md)，旧适配器转换和授权边界见[原生 MCP](MCP.md)。

当前绑定源码承接原生稳定性修复并保留既有严格工具、媒体确认及侧聊隔离；升级不会自动启用新供应商、配置本地决策模型或开放直接生图。Azure 旧 provider 名需按原生说明审查，不能把 API 标识或全部历史正文一起替换。新模型及思考等级以实际目录为准，不保证每个兼容网关支持。

## 保留的兼容边界

受管启动器、维护服务端接口、私有备份和恢复脚本保留兼容；内网 Windows 一键更新复用维护票据和启动器，其余设置页保留只读更新行为。旧客户端或经授权的外部集成仍须先检查启动器能力与空闲状态，按服务端一次性 review/execute 票据执行；网络/交接结果不确定时不要重复提交。`GET /settings/updates`、`POST /settings/updates/check` 省略渠道时默认包含预发布版；显式 `stable` / `preview` 参数仍供旧客户端使用。API 参数与错误边界见 [API](API.md#版本检查与-pi-受管维护)；受管备份不包括项目源码或外置链接目标，不能替代完整部署备份。

受管启动器默认保留最近 **5 个**经原生安装证明核验的发布目录和最近 **3 份**完整的更新前备份。Pivane 正式版与 `1.8.0-rc.1` 形式的预发布版使用相同的保留和恢复保护规则，Pi 依赖仍须是绑定的精确正式版本。当前运行版本、回退版本、两者各自最新的可验证原生停机备份，以及所有保留备份恢复时需要的发布目录始终保留，即使超出数量。删除旧项前先核验保留备份的 manifest、installation、对象字节和对应安装；当前或回退版本缺少可验证恢复点时跳过全部删除。未完成、损坏、未知或链接的发布／备份目录始终保留；没有完整备份不会使中断备份获得删除资格。备份范围仍以原生维护实际停机复制的范围为准，外部保存的停机备份不代替这里的原生证明。

实际自动删除目前仅在 Linux 的 `/proc` 目录描述符边界可用时执行；其他平台保留数据并在状态中记录 `skipped`，不退回路径删除。受管 runtime、releases、backups 和回收区须由当前用户独占管理、使用私有权限；安装根不得允许其他用户写入。所有合法写入者须遵守启动器安装锁和维护互斥。此边界防止越界、符号链接、合法并发及可检测的对象替换，不承诺抵御拥有同一用户任意文件系统写权限且故意绕过协议的进程。

清理在持有安装锁后、服务启动前和维护成功启动目标后执行；全过程占用维护准入，异步删除实际结束后才释放。删除前再次检查状态与固定目录描述符，先通过独占私有槽位隔离，再核对移入对象的身份并写入槽位证明；递归删除只处理仍匹配证明的树。它不使用内核的 no-replace rename 保证，槽位出现未知内容或身份变化时停止并保留现场。关闭过程取消后续删除并等待已开始的工作；已经创建但尚未就绪的子进程立即收到共享停止请求，不等待就绪超时，所有调用仍等待实际退出并保留失败；不重复提交清理或停止请求。已证明且未变化的待删槽位可在下次启动处理；未知旧回收区、证明缺失、内容变化或部分删除后证明不再匹配的槽位保留，不自动重放不确定删除。核验有明确预算：每轮备份对象累计最多 50 GiB／100000 项，每层受管清单最多 10000 个名字，每个隔离树最多 100000 项、128 层；核验对象在读取前以 manifest 声明字节数约束已打开描述符，单次读请求也不越过首次核验的大小；对象增长、短读或身份变化均拒绝证明。超预算或描述符不足时保留余项并报告状态。

可在实例 `.env` 用 `PIVANE_RETAIN_RELEASES`（至少 2）和 `PIVANE_RETAIN_BACKUPS`（至少 1）调整数量，设为 `off` 关闭对应类型的规划及**已排队回收区删除**；两者关闭时不核验或删除。上限配置不会覆盖恢复保护例外。维护状态的只读 `retention` 显示限制和最近清理结果，区分隔离数量、实际清除槽位数、跳过／失败／取消；主要维护操作成功而后续清理失败时分别报告。被删除的备份时间点无法再恢复，需要长期保存的备份应另行复制到外部存储。此策略不清理应用以外的维护工作区、归档或外部备份。

源码、当前运行快照和公开发布包各有独立版本身份。更新前保留尚未发布的修复，停机并保存相匹配的整批备份；切换后核对版本、会话与预约，失败时不要自动重放或将“已安装”当成“已验证启动”。

# Office 文档编辑与 MCP

当前源码内置固定版本 OfficeCLI，支持读取、创建和编辑 DOCX、XLSX、PPTX。它使用 Open XML SDK，运行不需要 Microsoft Office；已有公文规则检查继续使用[公文工具](GONGWEN.md)。源码完成不代表实际运行实例已更新或正式发行包已包含。

## 使用

在持久聊天上传 Office 文档并发送，例如：

> 检查这份合同中的名称、日期和金额是否一致，先列问题和修改建议，等我确认再修改。

审查按[文档一致性审查](DOCUMENT_REVIEW.md)执行。你在聊天确认报告版本和问题编号后，Agent 读取当前分支原件、准备工作副本，再使用 OfficeCLI 局部修改，检查后通过原生交付链接返回新文件。原件不变。也可以明确要求直接修改具体位置，或在项目中新建 Word、Excel、PPT。

`office-documents` 技能指导实际编辑：定位段落／单元格／元素，核对旧文本，使用局部替换并检查匹配数量。Word 可以记录修订作者，原有修订和批注仍需核对；跨文字片段的新文本继承匹配起点格式，整段重写可能合并原有混合样式，不能据此保证完整保格式。

## 文本与视觉检查

- 纯文本模型可以检查文字、结构、样式属性、修改差异和 Open XML 有效性，正常交付文件并注明“视觉排版未验证”。
- 支持图片的模型可以额外通过 MCP 接收页面截图，检查溢出、遮挡和布局。截图需要后端机器上的受支持浏览器；不可用时明确报告未验证。HTML 渲染与 Word/WPS 的字体和分页并不等同。
- 表格公式、缓存值和重算分别核对，不能用显示值覆盖公式；OfficeCLI 的计算支持不代表覆盖 Excel 全部函数及排版语义。PDF、旧 DOC/XLS/PPT、宏文件和插件格式不在首版编辑范围。

## MCP 在哪里运行

OfficeCLI 运行在白泽灵台后端所在的电脑。Pi 原生 MCP 自动启动 stdio 进程，无额外端口；服务器部署就运行在服务器，浏览器或手机访问不会直接获得本地文件权限。本机文件需先上传，修改后下载副本。

资源包 `pivane-officecli` 登记编辑技能及扩展，扩展在持久受管 RPC 会话注册 `pivane-officecli` MCP 服务器；连接、工具目录、取消和关闭继续由 Pi 官方 MCP 管理，不建立第二个客户端。默认以 Codemode 暴露，模型通过工具发现使用实际名称。每个启用的持久 worker 会自动连接自己的 stdio 进程，不是所有线程共享一个后台文档进程。

该服务器只暴露一个 `officecli` 工具，`command` 接受字符串数组；不是每个读写动作各有一个 MCP 工具。逐工具暴露无法进一步隔离读取与写入，聊天确认是 Skill 工作流，不是服务端审批票据。工具按后端用户权限执行，项目 cwd 和参数数组不是文件权限沙箱；原件存储保护及附件分支授权仍由白泽灵台执行。

受管模式允许文档读写、批处理、校验、帮助及截图等操作，禁用安装、配置、自更新、显式 resident／watch 和额外格式操作。OfficeCLI 本体使用过滤后的进程环境，不继承模型凭据、worker 内部访问 token 或 Node 注入选项。其自动更新、自动常驻均关闭；程序版本由应用管理。

在“扩展 → 已安装”中可分别停用编辑技能与扩展，保存后在空闲线程重载资源或重开运行实例。停用扩展后不注册准备工具和该 MCP 服务器；关闭原生 MCP 也不加载此扩展。运行时注册不写入用户的 `mcp.json`，用户同名已保存配置按 Pi 原生规则优先；需要复用此内置能力时保留服务器名。仅运行时注册的服务器暂不能按持久 MCP 配置授权给子 Agent，详见[原生 MCP](MCP.md)。

## 安装、版本和平台

程序版本、官方源码提交及各平台 SHA256 保存在 `config/officecli.json`；Apache-2.0 许可证、NOTICE 和传递依赖声明位于 `native/officecli/`。不运行上游全局安装器，不改 PATH、其他客户端配置或用户技能。

统一安装入口会准备并校验当前平台程序，存放于应用的 `native/officecli/bin/`。源码安装缺少程序时从固定版本的官方 GitHub Release 下载；已有校验通过的程序直接复用，离线安装需预先提供该固定程序。同平台归档携带构建机器已核验的程序，打包与受管源码快照使用相同清单；换平台后重新运行安装准备对应程序。缺失、哈希不符或平台不支持会明确失败，不会静默改用系统 PATH 中的其他版本。

可单独运行 `node scripts/install-officecli.cjs` 准备当前平台；损坏缓存不会自动覆盖，须先核对文件。运行时不下载或更新程序。清单列出 Windows、macOS、Linux 的 x64/arm64 及 Linux musl 版本；本次接入仅在 Windows x64 做原生执行验证，其他平台尚未实机验收。

## 文件和失败语义

上传原件编辑首期限 16 MiB。`prepare_office_document {id,requestId}` 只接收当前分支已发送附件的 ID，不接受模型指定的原件路径，也不将原字节传入模型上下文。

副本位于当前项目 `.pivane-office/<版本标识>/`，目录具备私有权限和内部 Git 排除规则，应用源码发现及发行同时排除用户工作目录。目录记录用于来源和准备完整性，不是独立对话库；原生分支记录保留有界副本索引，只向所属会话恢复；分叉会话需另行准备副本，交付后仍使用现有不可变快照。不会自动清理用户工作副本。

相同项目／原生会话／requestId 重用时返回**当前副本**，不会用原件覆盖已有编辑；换原件返回冲突，准备残缺时保留现场并拒绝重放。新版本用新标识。

OfficeCLI `batch` 默认整批失败回滚；多次独立调用、多个文件或整个 Codemode 脚本不因此成为事务。零匹配也可能 success=true，必须检查 matched。停止、超时和连接中断不证明修改取消或文件未变；先核对实际副本和原请求，不自动重放。交付前回读、校验并如实说明未验证范围，原件始终保留。

# 公文格式核验与草稿交付边界

新生成的公文和用户明确要求按规范修订的已有公文，以 GB/T 9704—2012 为格式核验依据；用户要求保留原版式的编辑不自动套用通用公文版式。此边界保护已有稿的编辑意图，避免一次文字修订扩大为整篇重排。

本轮核验覆盖电子文档可验证的字体、字号、颜色、标题层级、纸张与版心、缩进、行距、页码等格式要求，并逐项说明覆盖情况。结论称为“电子版式核验”，不扩大为整个国标全部合规；纸张材质、印刷装订、实体印章等另行验收。

每份公文在日常生成和规范修订时自动检查文件结构与最终生效的版式属性，交付判断依据本次实际完成的自动检查，不调用桌面 Word/WPS，也不要求用户逐份进行实机验收。没有逐份实机记录本身不阻止自动检查通过或正常交付；自动检查结论不扩大为已验证所有办公软件的实际显示效果。

发现格式问题、缺少所需字体或必要自动检查未完成时，允许交付草稿，但应列出问题，区分已确认不符合与尚未验证；不得把未满足对应检查条件的草稿标为“电子版式核验通过”。允许带问题交付，旨在保留审阅与继续修改的工作流；“规则机检通过”仍只代表已经执行的规则未发现拦截错误。

本轮沿用现有小标宋、仿宋、黑体、楷体、宋体的字体组合，补齐所需字体缺失的识别和报告，不新增面向用户的字体配置入口。不自动下载字体或把指定字体改为其他字体；字体替代不能当作原指定字体已经核验通过。

“保留版式”同时保护字体、字号、粗斜体和颜色，文字修订不顺带改变这些字符属性。相关规范问题先报告，明确获准后再修改对应属性。

用户明确要求规范修订时，允许在副本中直接调整字体、段落和页面属性，另提供可定位的格式变更清单；文字保留修订痕迹，原件保留供恢复。本轮不要求每项格式变更都作为 Word 格式修订逐条接受或拒绝，不能通过拒绝文字修订撤回的直接格式调整须明确说明。

首批开发阶段的代表性样本分别以 Windows Microsoft Word、WPS 做实际显示效果回归，网页预览另做一致性检查；这些实机脚本不是日常生成路径的依赖。各目标的软件与核验范围单独记录，未验收的软件明确保留缺口，样本结果不冒充每份文件的实机记录。

网页预览优先修复与文档的一致性；仍不能准确呈现时，明确显示“近似预览”或“暂不支持”，保留原文档下载。已确认的预览错误记为未通过，缺少必要条件而未完成的核验记为未完成，不能用降级预览支持通过结论。

以上为已确认的设计边界，整体实现方案待访谈结束时确认；本决策不表示代码已实现、运行实例已更新或实机验收已通过。现有行为见[公文指南](../GONGWEN.md)，领域用语见[术语表](../../GLOSSARY.md)。

# 人员调配

人员调配是白泽灵台的内置可选能力，默认关闭。当前台账由调配模块保存，与聊天正文分开。删除聊天不会释放人员占用。本文说明源码行为，不表示已部署或公开发布。

## 首次启用

在扩展发现页打开“人员调配”。按引导创建专用助手，用标准 Excel 导入人员、当前及已知未来的项目、预占、请假和培训记录，再核对初始台账。也可展开“高级台账输入”使用 JSON。不要把缺少占用记录当作已经核实空闲。再次启用会沿用原台账及绑定的助手，保留自定义助手名称和说明。

首次启用中断时，在页面点击“继续初始化”。它使用原初始化操作，沿用已创建的专用助手；不要另建助手来代替恢复。

人员使用稳定编号。人员字段为 `id/name/department/direct`，其中 `direct` 表示与本公司直接签订劳动合同。项目字段为 `id/name/owner/department/start/end/minimum`。日期使用 `YYYY-MM-DD`，包含首尾。`minimum` 是最低人数。

这里的项目是用人业务项目，以项目编号识别。它与聊天工作目录、助手会话分类分别管理。同一 Pi 身份使用同一人员台账，切换聊天目录或分类不会创建新台账。

## 在聊天中安排人员

打开引导中的“人员调配智能体”链接。例如提出：“A 事业部的新项目，11 月 1 日到 5 日需要两人。”补齐项目编号、名称和负责人后，助手查询最新台账并推荐完整名单。推荐不会占用人员。已有项目会分开返回已安排人员和本次新增名单。例如最低 5 人、已预占 3 人，只推荐补充 2 人；仍可由负责人主动超额安排。

默认只查本事业部。候选人员在整个用人日期范围内必须没有预占、正式安排、请假或培训。排序按用人开始日前 90 天内已登记的项目安排天数，从少到多；同分按稳定编号排序。优先保证一名可用直签，再补足人数。历史不完整时会提示局限。人数不足或缺直签时如实显示缺口。

助手准备方案后，聊天显示人员安排卡片：

1. 核对项目、事业部、日期、最低人数、本次选中人数、人员编号和每日缺口。有已有团队时，卡片分开显示已有安排人数与本次新增人数。
2. 如需换人，修改勾选，再点击“检查调整后的名单”。修改后不能直接确认旧名单。
3. 如需借人，勾选“仅此方案允许跨事业部查询和借人”，检查方案后再选择其他事业部人员。这项许可不适用于下一个独立方案。
4. 点击“预占”或“正式确认”。聊天中的肯定答复不代替按钮确认。

预占和正式安排都计入占用。允许部分预占；人数和直签缺口会继续显示。安排达标与全部正式确认分别判断。服务器在提交时重新检查最新台账；两个聊天不能重复安排同一人。旧方案失效后，需要重新查询并准备方案。

结果不确定时，卡片保留原操作编号，并提供“查询原操作结果”。不要重新提交。刷新后会核对原方案和结果，不自动重复占用。卡片中的候选预览最多显示 200 人。

如果方案已保存，但会话进程在卡片消息写入前退出，专用聊天可以查询原操作编号，找回同一方案卡片。查询不会重新准备方案或占用人员。旧方案仍须通过当前台账、来源及启停代次检查。

## 三个视图与手动调整

“人员调配”页面提供可用人员、项目安排和人员日历。三个视图与聊天读取同一台账，并显示修订。记录分页显示，不把当前页当作完整清单。可用人员按事业部和完整日期筛选；项目按日期区间显示实际人数、直签和缺口；人员日历同时显示项目、预占、请假、培训和已释放安排。

每页最多 200 条，且完整 JSON 响应最多 512 KiB。服务端可以减少本页条数，通过 `nextOffset` 指向下一页；末页返回 `null`。每条记录的人员和日期明细保持完整。单条记录已超限时明确返回 413。人员日历可缩小查询日期范围；项目视图保留完整项目区间，单个项目记录超限时可导出 Excel 核查。

在页面选择项目和操作，点击“检查变更方案”。检查卡片中的原记录、新记录和受影响日期，再点击“确认以上变更”。页面方案使用服务器建立的页面来源，不要求先创建聊天，也不写入原生 JSONL。聊天来源方案仍核对原生分支引用。

- 登记请假、培训或不可用时间会保留原项目安排，按对应日期标记人数和直签缺口。系统不会自动调走其他项目人员。
- “将已有预占正式确认”只改变既有安排状态，不重复增加人员。安排达标与全部正式确认继续分开显示。
- 区间换人只替换明确指定的未来日期。原人员其他日期的安排保留。跨事业部替换须在该具体页面方案中明确允许，下一方案恢复默认范围。
- 未来项目可以整体改期。已开始项目不能回溯整体改期，应使用未来延长、提前结束或区间换人。有分段团队的项目应使用明确的区间调整。延长会检查新增日期是否有占用。
- 撤回人员、取消项目和提前结束均指定“释放开始日”。该日是首次释放日，前一天是最后用人日。以服务器本地日历判断未来日期。已发生的占用保留，继续参与近 90 天排序；释放部分保存为历史。预占不会自动过期。

项目可含 `lifecycle`：省略或 `{state:"active"}` 表示正常；`{state:"cancelled"|"ended",effectiveDate:"YYYY-MM-DD"}` 表示从该日取消用人要求或提前结束。原项目范围保留作为历史范围。已释放占用可以位于当前项目日期范围外；有效占用必须在当前项目范围内，并在释放日之前结束。

## 启停与上下文

停用关闭操作入口和工具，保留台账、方案及历史。重新启用后，旧方案仍不能提交。专用会话应显式重新加载资源或退出后重新打开，再继续请求。

Skill 索引与工具定义只加载到已验证的专用原生会话。普通新对话、其他助手和无档案对话不增加调配上下文。卡片的布局代码不进入模型提示词。已有历史中的相关消息和工具结果仍保留原生语义。

专用工具的模型文字结果最大 64 KiB。查询保留完整选中人员编号、直签标记和工作天数，姓名候选仅作部分预览；完整姓名及编号由卡片从台账读取。完整编号超出预算时明确失败，不返回冒充完整团队的截断名单。卡片引用元数据另有 64 KiB 上限，保留完整来源路径，不携带完整人员或项目清单。

显式配置文件 URL、`~` 或 Windows 路径别名，也按资源的真实位置检查，不能把调配资源加载到普通会话。

从专用调配会话打开侧聊时，请选择“空白背景”。需要时可追加选中文字。该来源不支持复制完整上下文，停用后仍适用。系统不会静默更换背景，也不会删改用户提示词。协议兼容规则见[侧聊接口](SIDE_CHAT.md)。

## 保存冲突与恢复

保存提示修订或占用冲突时，先刷新核对最新记录，再准备具体方案。保存超时、断线或返回“结果未知”时，保留原操作编号，使用“查询原操作结果”。返回待定或未知时继续核查，不能推断写入失败，也不能换编号重复提交。初始化中断使用“继续初始化”；Excel 导出使用原导出操作查询。

若错误提示 `Unknown legacy storage lock`，表示发现旧版 `ledger.lock` 或 `profiles.lock`，服务不会自动删除。升级前需停止全部旧版写入进程；在停机备份和维护中核查旧锁。不要按文件时间或 PID 猜测锁已失效后直接删除。提示其他进程正在保存时，等待该操作结束后刷新；提示存储所有权不可用时，先处理运行环境问题。存储协议见[档案存储互斥](development/AGENT_PROFILES.md#存储互斥与保存恢复)。

## HTTP 接口

以下路径都位于 `/api/pi/staffing`，使用现有工作台访问和 Origin 校验，响应禁止缓存。它们不增加独立的多用户权限系统。

| 方法与路径 | 用途 |
|---|---|
| `GET /status` | 能力状态、修订、epoch、专用档案及初始化进度 |
| `GET /views?kind=availability/projects/people/history` | 同一修订的可用人员、项目覆盖、人员日历或变更历史，支持有界分页 |
| `POST /recommend` | 页面查询已有团队、缺口及推荐新增人员 |
| `POST /prepare` | 页面准备新增人员方案 |
| `POST /adjust` | 页面准备请假、正式确认、换人、改期、延长或释放方案 |
| `GET /ledger` | 已启用台账的人员、项目及占用 |
| `POST /enable` | 启用或恢复原初始化操作 |
| `POST /initialize` | 导入待核对的初始 JSON 台账 |
| `POST /confirm-initial` | 显式核对初始台账，`reviewed:true` |
| `POST /disable` | 停用并提升能力 epoch |
| `GET /operations/:requestId` | 核对原操作结果；未知结果不授权重放 |
| `GET /plans/:planId?cwd=…&sessionId=…` | 获取当前分支上的方案及已保存结果 |
| `POST /revise` | 页面检查具体调整，生成新方案版本 |
| `POST /commit` | 页面提交具体方案，`action:reserve/confirm/apply` |
| `POST /agent/query` | 私有受管 worker 查询及推荐 |
| `POST /agent/prepare` | 私有受管 worker 准备卡片 |
| `POST /agent/operation` | 私有受管 worker 核对本来源操作 |

写操作使用稳定 `requestId` 与 `expectedRevision`。同编号同参数返回原结果；同编号不同参数返回冲突。`409` 表示修订、占用、能力状态或互斥冲突；`403` 表示来源或页面确认身份不符；`413` 表示预算超限。保存故障或断线应查询原编号，不推断取消。

查询输入为 `{kind:"recommend",project}`。准备输入为 `{requestId,expectedRevision,project,personIds}`。页面调整输入为 `{requestId,expectedRevision,planId,personIds,allowCrossDepartment,source:{cwd,sessionId}}`。页面提交输入为 `{requestId,expectedRevision,planId,action,source:{cwd,sessionId}}`。页面方案读取使用 `?kind=page`，提交使用 `source:{kind:"page"}`，档案绑定由服务器提供。变更准备输入有 `kind:absence/formalize/replace/reschedule/extend/release`，释放输入同时指定 `releaseKind:withdraw/cancel/early-end` 和 `effectiveDate`。模型工具没有提交或许可开关。

聊天来源由实际原生 SessionManager 核对，聊天方案必须在当前原生分支中有工具结果引用。页面方案只由通过工作台认证的页面入口建立，worker 不能自报页面身份。私有 worker 请求使用当前受管 worker 的私有认证，验证档案和已加载 epoch；此认证不能调用页面确认接口。不要在提示词、客户端存储或日志中放置该凭据。

台账位于 `<Pi agentDir>/pivane-staffing/ledger.json`，是受保护的身份私有 JSON 文件，最大 8 MiB；人员及项目各最多 5,000 条，占用最多 20,000 条，操作及方案各最多 10,000 条，历史最多 20,000 条。超限明确失败，不把截断结果当作完整台账。日常备份沿用身份目录的既有备份边界。

## Excel 导入与成果

启用后可以下载合成示例 XLSX。标准文件包含人员清单、项目需求、人员安排、其他占用、项目检查和导出说明六张工作表。首行为稳定字段名；人员、项目和占用使用明确 ID，重名不合并。日期填写 `YYYY-MM-DD` 文本，直签填写 `true/false`。项目生命周期使用 `lifecycleState` 和 `lifecycleEffectiveDate`，释放后的过去有效记录和取消记录保留。

选择 XLSX 后点击“检查 Excel 差异”。页面展示新增和修改、原件版本及变更数量；大批量仅在卡片显示部分记录，需同时核对完整原件。点击“确认导入”才提交。首次导入完成后仍须核对初始台账。后续导入按 ID 合并，不因文件缺行删除记录，不隐式恢复已释放人员或重新开放已关闭项目；跨事业部新安排须使用明确允许借人的安排方案。新增安排不能覆盖请假或培训日期；已有安排遇到后来登记的请假会保留，并显示实际缺口。

解析在受限独立进程完成。原件最大 20 MiB；宏、公式、外部关系和非标准日期会被拒绝，不执行公式或使用缓存结果替代事实。全量解析超预算会明确失败，不会仅导入前 200 行。导入原件与报告分别最多占用 256 MiB 私密存储，并有条目上限；台账仍受自身 8 MiB 限制。

就绪后可点击“导出并保存到成果”，或明确要求专用智能体导出。XLSX 固定同一台账版本，标明生成时间和版本，文字按字符串写入。导出文件最大 16 MiB，单个 XML 部分最大 8 MiB。返回 `generated` 仅表示已生成，`available` 表示已登记可核验的生成来源，`saved` 才表示成果库已有独立副本。成果保存失败不撤回人员安排，也不报告已保存。生成来源使用服务端导出操作证明，不伪造原生交付或会话记录。已保存副本在删除来源聊天或停用能力后仍可使用。

后续台账变更不会改写已生成报告的版本或字节。尚未独立保存的生成来源仍须通过启用状态、启停代次和原来源资格检查；已保存副本按成果库规则使用。

新增接口（以下仍以 `/api/pi/staffing` 为前缀）：

| 路径 | 用途 |
|---|---|
| `GET /excel/template` | 下载合成示例模板 |
| `POST /excel/uploads?requestId=…` | 页面上传 XLSX，`application/octet-stream` |
| `GET /excel/uploads/:requestId` | 核对原上传结果，不重放 |
| `POST /excel/import` | `{requestId,expectedRevision,uploadId}` 准备差异 |
| `POST /commit` | `action:apply-import`，页面来源选择器为 `source:{kind:"page"}` |
| `POST /excel/export` | `{requestId,expectedRevision}` 导出并保存成果 |
| `GET /excel/operations/:requestId` | 核对原导出阶段、哈希和成果结果 |
| `GET /excel/exports/:exportId` | 经过原生成来源校验后下载固定报告 |
| `POST /agent/import` | 私有工具用 `attachmentId` 准备标准 XLSX 差异 |
| `POST /agent/export` | 私有工具按需导出 |
| `POST /agent/export-status` | 私有工具核对原导出结果 |
| `POST /agent/ledger-status` | 私有工具读取当前版本和数量，供导入导出使用 |

页面来源由服务器构造；页面不能提交档案 ID 冒用专用 worker。聊天导入仍需要当前原生分支中的真实工具结果引用。导出结果不确定时保留原操作编号并查询，不自动创建新导出。Excel 是当前业务快照，完整操作历史仍以台账和备份为准。

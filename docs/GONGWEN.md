# 公文生成 检查与修订

当前源码内置公文生成、检查与规范修订能力，使用固定版本 gongwen-kit 的版式构件和规则处理 Word，并返回电子版式、数字、文风检查报告。源码完成不表示已有运行实例已更新或正式发行包已包含该能力。

## 使用

在持久聊天里直接描述任务，例如：

> 起草一份培训通知。主送各部门，培训时间为 2026 年 10 月 20 日上午 9 点，地点为第一会议室，落款为示例单位，成文日期为 2026 年 10 月 15 日。生成 Word 并附检查报告。

也可以通过现有 `/` 技能联想使用 `gongwen`。支持通知、报告、请示、函、纪要、管理办法和非红头企业文书。默认不加红头；明确要求红头时提供发文机关、文号、签发人等相关要素。文种和措辞仍由当前聊天模型根据任务决定，生成工具负责结构、版式及规则检查。

时间、地点、金额、人数等影响正文的事实缺失时，Agent 先集中询问。要求直接出稿时使用明确占位，结果标为待补充草稿；落款、日期和必要主送缺失也会自动留占位。单位信息沿用当前会话或用户明确选定的提示词模板，不自动建立跨会话默认单位。

工具完成后返回 DOCX 与 Markdown 检查报告两个原生交付链接，聊天回复概述状态和待核对事项。DOCX 在网页提供下载，报告可直接预览。需要长期保留时，可将交付保存到[成果中心](ARTIFACTS.md)。

新文件按文档标题和稳定版本标识命名，例如“培训通知-12位版本标识.docx”和“培训通知-12位版本标识-检查报告.md”；修订件、受检原稿再加对应后缀。文件名会清理不适合路径的字符、截短过长标题，同标题的新请求也能区分。旧文件名及历史交付保持不变，同一请求仍返回原文件。

新稿工具 `generate_gongwen` 成功返回的实际文件也会在本轮结束后的“本轮文件”中标注为“已交付”，可从这里打开交付快照、预览或下载。同轮同标题的多次生成分别保留，并显示标题、第几版、返回的检查状态；有多版时最后生成的一版标记“本轮最新”，不代表已经审批。版本号只在该轮、同一标题内排序。旧版同名公文也能据此区分；重复返回旧交付不会改变最新标记。若本次只交付检查报告，列表也只显示报告。未压缩的已有工具结果无需重新生成即可显示。

## 检查与修订已有 Word

上传 DOCX 并发送到当前聊天后，可说“只检查这份公文”或“按公文规范修复，另存带修订痕迹的 Word”。工具通过附件 ID 读取当前原生分支有权访问的原字节，不使用模型提供的文件路径。

- **只检查**：交付受检原稿和报告；受检文件与上传原件字节一致。
- **规范修订**：另存修订公文，原件不变。通用公文的版心、字体、行距、页码等可直接调整；报告另列可定位的格式调整前后值。确定性的文字规范修改写成 Word 修订；数字合计等疑点写成批注。修订完成后重新检查最终生效属性，仍有偏差时交付待核对草稿。
- **保留版式**：可明确说“保留原版式，只做规范文字修订与批注”。字体、字号、粗斜体和颜色随文字修订保留；函、纪要、封面及特殊模板默认按此处理。此时格式仅作参考，不因保留了不符合通用公文的属性而自动重排。版式直接调整不能通过拒绝文字修订撤回，需从原件另做保留版式的版本。

在 Word/WPS 的审阅功能中逐条接受或拒绝本轮修订、查看批注。报告按建议修订后的可见文字检查；机检通过不表示你已经接受修订。原稿已有修订和批注继续保留，原审阅人仍需确认。拒绝本轮文字修订后正文应与原稿一致；表格内文字与数值、版头、文本框及不透明内容保留，问题通过检查报告与批注提示。

带主题色的原稿会保留版式，报告说明未执行版式调整。未声明表头、合并或嵌套表格等不能按完整数表严格核对时会列出覆盖提示。数字签名或不支持的结构不能自动修订；若已有结构有效的原稿检查点，交付受检原稿并明确处理未完成。文件损坏或结构验证未完成时只交付失败报告。

首期处理不超过 16 MiB 的 DOCX；暂不支持旧 DOC、含宏文件、Office 在线编辑和 PDF 转换，也不执行用户提供的任意正文改写脚本。上传原件仍保存在既有附件存储中。

## 状态与改稿

| 状态 | 含义 |
|---|---|
| 规则机检通过 | 已执行规则没有发现拦截错误；当前文件的 Word/WPS 字体与分页仍未实机核验 |
| 待补充草稿 | 存在缺失事实或明确占位，报告同时列出其他问题 |
| 待核对草稿 | 存在检查错误或需人工核对的提示，不能作为已核定稿使用 |
| 检查未完成 | 检查程序失败、超时或异常退出；已有结构有效的文件可作为草稿交付 |
| 生成失败 | 尚无经过结构验证的 DOCX，只交付失败报告 |

新稿的格式、编号、日期写法、异形词等确定性问题最多自动规范修正两轮。已有稿一次规范修订后重新检查，文字改动由用户审阅；直接格式调整与文字修订单独显示。引用原话、网址等保留；表格数字不自动修改，正文金额事实也不猜改。风格提示可按语境保留。

长报告会明确标记节选并保留问题总数；文字修正记录、原始与最终草稿源保存在该版本的项目私有目录，单项最多 1 MiB。直接格式调整另存“格式调整.json”，保留总数和节选标志；生产侧最多记录 200 项，超出时不称完整清单。展示报告还按共享预算节选。节选不掩盖检查错误或将故障改成通过。

后续说“把地点改为第二会议室”等，Agent 根据已保存的草稿源生成新版本，并重新检查，旧版本保留。不同版本使用不同请求标识；丢失响应只能核对同一请求的已有结果。已登记但没有完整保存的操作不自动重放，须核对文件后明确发起新请求。

## 数字和字体边界

- 金额、整数数量和明确的十进制数列按显示值做严格合计，采用定点计算，不能让 0.5% 的相对容差掩盖差错。保留小计分段与总计规则。
- 占比允许与各分项及合计显示小数位相符的舍入范围；只有明确声明完整构成的列才严格核对 100%。部分构成不据此判错。
- 自动识别常见金额／数量／占比表头；未识别的合计表、非纯数字、缺失值或范围列入覆盖提示。正文同指标取值和正文／表格对照属于启发式提示，时间、单位和口径仍需人工判断。
- 新稿及执行通用版式规范修订的 DOCX 声明小标宋、仿宋、黑体、楷体和宋体，应用不捆绑、下载或自动替换字体。本机字体可用性与文档属性分别报告；Windows 可枚举已安装字体族，其他平台或探测失败标为未知。结果不证明打开设备、字形覆盖或办公软件实际选字。标题字体表声明宋体备选，避免部分 WPS 环境按相近名称选中书法字体；备选不代表小标宋验收通过。
- 规则机检不证明事实真实、政治表述正确、审批完成或已经加盖印章。

## 电子版式与预览

新稿和明确要求规范排版的修订，按 GB/T 9704—2012 的适用电子属性核验。新稿使用唯一的公文样式，标题二号小标宋 22pt 居中、正文三号仿宋 16pt，层次标题使用相应黑体、楷体或仿宋；表格、版记、红头、条文体和信函等按各自角色处理。

检查读取最终 DOCX 的文档默认值、段落／字符样式继承和直接格式，逐项列出位置、预期值和实际值。已实现的范围包括字体、字号、颜色、粗斜体、对齐、正文缩进与行距／网格、各节 A4 纸张及版心、编号标记和页码。重复、循环、悬空或错误类型的样式引用不能认定为通过；主题属性、复杂脚本或无法可靠识别的角色等缺口明确列出未完成或不适用。

主送机关按顶格要求单独核验，不套用正文的二字缩进；无法可靠区分主送与正文时明确列出未完成。行网格检查段落实际所属节、网格是否启用及段落的继承设置，未启用的网格不能证明行距；页码同时核对黑色和正体要求。正文、页眉与页脚使用相同的属性继承和样式类型检查。

报告分别给出电子属性、所需字体可用性和综合结论。属性通过而字体缺失／未知时，综合电子版式核验仍未完成，文件作为待核对草稿交付；保留版式和只检查原件的通用格式结果仅供参考，不认定整篇合规。结构机检限于有界 XML、样式引用及关键不变量，并非完整 Open XML SDK 校验，也不覆盖纸张材质、印刷装订和实体印章。

日常生成和修订自动执行这些检查，不调用 Word/WPS，也不要求逐份实机验收；没有 Word/WPS 记录本身不导致规则机检失败。实际字体、换行和分页另属实机显示核验，开发样本回归也不代表任意文件已验收。

网页展示若未验证与原件一致，应标为“近似预览”或“暂不支持”，保留 DOCX 下载。HTML 可用于阅读，报告中的预览未核验状态不代表已完成 Word/WPS 显示检查；通用文件预览的支持范围以[文件查看器](FILE_VIEWER.md)为准。

## 启停、存储与预算

随应用交付，默认可用。扩展的已安装资源中可分别启停 `pivane-gongwen` 的技能与生成／修订扩展；停用扩展后不会注册 `generate_gongwen` 和 `revise_gongwen`。保存开关后，在空闲会话重载资源或重开运行实例，沿用[内置能力包](BUNDLED_CAPABILITIES.md)的范围、信任和版本管理。

生成与检查在无模型凭据的独立 Node 进程执行，192 MiB V8 堆、30 秒预算、每个服务实例最多两项在途操作。取消后等待进程实际退出；原生工具调用和会话停机继续走唯一受管 worker。模型起草的数据流仍取决于当前模型，排版与规则检查不调用外部服务。

新稿输入最多 128 KiB；正文最多 300 构件，正文与附件合计最多 500 构件，附件最多 5 个；每表最多 200 行、12 列，每格最多 512 字符。DOCX 输入与输出最多 16 MiB，报告最多 256 KiB；已有稿修订记录最多 1 MiB、5000 条，批注最多 500 条。Office 展开量、XML 部件及结构校验沿用有界解析器；超限不认定修复通过。

项目中的 `.pivane-gongwen/<版本标识>/` 保存私有草稿源、DOCX、报告及结果凭据，只创建新文件，完整请求可复用，残缺结果不重放。目录自带仅排除内部文件的 Git 规则；应用 Git 规则与发行源码发现另行排除该目录，不改用户项目的主 `.gitignore`，也不清除已提交的历史。该目录不是会话事实来源，不自动清理。下载使用现有不可变[交付快照](FILE_VIEWER.md#交付物图片与-html)，访问资格仍由当前原生分支证明。

精确上游提交、源码来源与逐文件哈希在 `vendor/manifest.json`；依赖版本由根 lockfile 管理。字体授权与上游限制见 [gongwen-kit 字体说明](https://github.com/imhuhe/gongwen-kit/blob/d8dfe6a24e20ecaa64c14f3a79159813ad92db70/docs/字体.md)与[接入评估](development/research/gongwen-kit.md)。

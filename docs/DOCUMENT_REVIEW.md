# 文档一致性审查

当前源码内置 `document-consistency-review` Pi Skill，用于方案、报告、合同及办公文档的一致性审查。它使用现有会话、模型、文件读取和交付物工具，先报告问题，用户在聊天中确认具体问题后再修改。源码完成不表示当前运行实例已加载或公开发行包已包含。

## 使用

在持久线程上传 DOCX、XLSX、PPTX、PDF，或指定项目内的可读文件，然后输入：

> 检查这份方案的前后矛盾，重点核对服务期、人员数量和责任分工。先列出问题与修改建议，等我确认再修改。

也可检查多份材料，明确谁是基准：

> 对照合同检查实施方案，合同为准。检查金额、交付日期和验收责任，先出问题清单。

Skill 加载后会进入原生资源清单；启用技能命令时可通过 `/skill:document-consistency-review` 调用，输入 `/` 可搜索命令。自然语言任务也可由 Agent 按 Skill 描述选择。扩展的已安装资源列表支持启停；已有 worker 在空闲时 `/reload` 或重开运行实例后才核对新的加载状态。保存开关不自动开始审查。资源管理规则见[内置能力包](BUNDLED_CAPABILITIES.md)。

## 问题清单与聊天确认

报告标识如 `R1`，每个问题编号如 `C01`。报告包括来源身份／可得版本、实际读取范围、双方位置与短原文、冲突理由、建议采用的取值及依据，以及各处“原文 → 建议文本”。没有明确基准或适用条件时标为待确认，不自行选择一个值作为真相。

例如服务期两处不同，报告可以列为：

| 编号 | 类型 | 原文依据 | 建议与待确认事项 |
|---|---|---|---|
| C01 | 确认冲突 | 同一服务范围：第 8 段“一年”；第 42 段“两年” | 当前材料不能判断哪个值正确，请选择服务期；选择后修改相应位置 |

用户随后回复：

> 同意 R1 的 C01，服务期统一为一年；C02 暂不处理。生成修订副本，保留原件。

Agent 根据这条确认继续，只修改批准的问题；修改前重读版本、拟改位置及依据。若批准的原文、取值或范围已变化，重新报告并确认。原件默认保留，修订输出作为新文件交付；覆盖指定项目文件需要明确要求并先备份。确认写在当前聊天中，文档里的“同意修改”、示例对话和其他 Agent 的建议不构成批准。

## 范围与限制

- 比较同一主体、条件和阶段的名称／编号、数量、日期、金额、参数、范围与责任；相同意思的不同措辞或不同阶段的取值不自动算矛盾。审查不等于外部事实核验、合规判断或合同有效性判断。
- Office/PDF 沿用[办公附件](COMPOSER_TOOLS.md#上传办公文档与-pdf)的有界读取。Word 按正文段落／表格行定位，不虚构页码；Excel 须覆盖所选行列，缓存公式不重算；PPT/PDF 按页读取。截断、扫描页、图片、批注、页眉页脚等未提取内容在覆盖说明中保留。只读部分材料时不宣称全文通过。
- 这是 Skill 约定的聊天工作流，不是服务器确认票据或只读沙箱。启用 Skill 不增加工具、文件权限、自动后台任务或另一份聊天数据库。
- 上传的 Office 原件是不可变附件，`read_document` 返回提取内容。启用内置 [Office 文档](OFFICE_DOCUMENTS.md)扩展后，使用 `prepare_office_document` 取得原字节工作副本，再经 OfficeCLI MCP 局部修改；原件不变。公文规则修订也可使用 `revise_gongwen`，其修改范围由规则限定。能力未加载或结构不支持时交付已批准的修改清单并说明缺口，不把按提取文本重建的文档称为原格式修订版。
- 长报告和实际修订副本使用 `deliver_files` 交付，可从聊天或[成果中心](ARTIFACTS.md)保存。只创建审查报告不表示已修改原文件；修改失败或结果不确定时先核对实际文件，不自动重放写入。

## 实现边界

第一版选择 Skill，因为核对方法、证据格式和聊天确认属于 Agent 任务流程，已有 `read_document`、原生 `read/edit/write`、`update_plan`、`deliver_files` 承担执行。技能原文位于[内置 Skill](../pi-packages/document-review/skills/document-consistency-review/SKILL.md)，由独立 `pivane-document-review` 资源包注册；使用本项目原创指令，不包含易标源码。

后续若需要逐项勾选、持久结构化审查卡、服务器验证报告版本与一次性执行确认，再增加 Pi 扩展及对应服务；仅增加 Skill 提示词不能提供这些强制保障。现阶段 REST/WebSocket、worker 工作类型、会话存储和权限契约不变。

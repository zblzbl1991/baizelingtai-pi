## Question

怎样用轻量原生管理窗口清楚表达服务状态、可用动作、停机阻碍事项和日志，同时保留默认浏览器入口与窗口默认隐藏的已确认行为？

## Context

现有 [托盘脚本](../../../scripts/desktop-tray.ps1) 使用 Windows Forms，[EXE](../../../native/pivane-desktop-launcher.cs) 是 .NET Framework 4 的薄入口。优先比较复用现有技术栈的窗口方案；引入 WPF/.NET 10 属于额外依赖与发行决策，不能直接复制上游。

## Prototype scope

用合成状态制作可供用户判断的低成本原型，至少展示运行、已停止、正在停止、停机被阻碍、启动失败、停机失败及未知状态。原型不连接真实实例、不发停机请求、不自动打开模型或媒体任务。

## Completion criteria

- 用户确认窗口信息层次和状态/动作矩阵；停止服务与退出白泽灵台的文字及结果明确，窗口关闭动作表示隐藏。
- 默认仅显示摘要；近期日志可展开，完整日志沿用现有文件入口，私人正文和凭据不成为默认内容。
- 验证托盘双击恢复窗口、右键菜单、最小化、重复打开、键盘操作和高 DPI；错误展示保持原定浏览器／托盘策略，不默认弹窗抢焦点。
- 原型回答的是布局和行为决策；产物链接与用户结论放在 Answer，不直接当作生产实现或 Windows 实机验收。
- 最终列出实施需同步的 [桌面指南](../../../docs/DESKTOP_LAUNCHER.md)、[模块导航](../../../docs/development/MODULES.md)、API/私有协议契约与 CHANGELOG，以及源码、二进制、manifest 和统一发现清单要求。

## Answer

采用 A「紧凑控制窗」。状态、工作台地址与服务操作集中在一屏，近期日志默认折叠，完整日志保持独立入口。B 的分栏和 C 的常显诊断记录保留为对照原型，不进入首批实现。

### 实施时保留的界面层次

1. 标题栏使用白泽灵台名称与现有图标；窗口关闭与最小化均保留托盘，默认浏览器启动不自动显示管理窗口。
2. 主区域首先显示真实服务状态与简短说明，其次提供工作台地址、程序目录和浏览器信息。未知状态显示最后已核实信息，不误报成功或已停止。
3. 主操作按状态显示“打开工作台”或“启动服务”，并提供“停止服务”；底部单独放置“退出白泽灵台”，使保留管理入口和退出整个托盘的后果可辨认。
4. 近期日志按需展开，完整日志沿用本次运行文件。停机被阻碍时就地展示有界类型、数量、名称及进入工作台的入口，不默认展示会话正文。
5. 保存草稿确认、最终重查、启动/停机期间动作禁用和未知结果处理，以 [停机事务](03-stop-transaction.md) 与 [服务代次](02-service-generations.md) 为准。慢启动、重新连接与稳定等待地址按 [等待页恢复](06-startup-recovery.md)；预约提示按 [预约兼容](04-scheduled-misfire-policy.md)。

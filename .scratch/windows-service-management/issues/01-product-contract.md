## Question

Windows 桌面入口的服务管理体验应解决什么问题，启动、窗口、停止、退出、故障和预约的用户可见行为分别是什么？

## Answer

本票据归档此前已完成的批量 grilling；用户逐轮接受推荐，明确调整默认浏览器行为，最终回复“确认方案，形成wayfinder”。以下为确认后的产品约定，不是当前功能清单。

### 目标与范围

首要目标是让用户不用打开终端，就能判断服务正在启动、运行、停止、失败或仍在等待。首批覆盖 Windows 手动启动与托盘模式；管理自身拥有的实例。已有后台服务和未知端口占用者只显示原因及处理入口，保留其原管理方式。

### 启动、浏览器与管理入口

| 用户动作或场景 | 确认行为 |
|---|---|
| 首次双击 EXE | 自动启动服务，默认直接打开系统默认浏览器，保留既有临时等待页到正式工作台的流程 |
| 服务已启动时再次双击 EXE | 打开该实例工作台；启动中沿用已有等待页，不建立第二个服务 |
| 服务已停止、托盘仍在时双击 EXE | 手动触发重新启动，再按正常浏览器流程打开工作台 |
| 双击托盘图标 | 恢复并显示已有服务管理窗口 |
| 右键托盘图标 | 菜单提供“服务管理”和独立“打开工作台”入口 |
| 关闭管理窗口 | 窗口隐藏，托盘及服务继续运行 |
| 关闭浏览器 | 服务继续运行 |

管理窗口为复用现有托盘的轻量原生窗口，默认隐藏。默认浏览器启动不改为 PWA，不修改系统浏览器偏好。

### 管理窗口的信息

默认显示实际运行状态及简短错误，提供“展开近期日志”和“打开完整日志”。继续复用本次运行日志及脱敏，不引入重复日志历史。

停机阻碍项显示工作类型、数量和可定位的任务名称，提供进入工作台处理的入口；默认不展开会话正文。管理窗口用于查看、定位和服务控制，任务取消仍在对应工作台入口完成。

### 停止、退出与阻碍事项

“停止服务”在正常停机完成后保留管理入口和托盘，用户可重新启动；“退出白泽灵台”在正常停机完成后退出整个托盘程序。

Agent、Shell、媒体等工作或待处理状态存在时，展示阻碍事项，本次停机请求结束。用户处理后再次点击停止或退出；不能留下自动等待空闲后执行的请求。服务端空闲检查通过后，仍提醒保存浏览器草稿与未提交编辑，并要求用户确认停机。

确认期间状态可能变化，最终提交必须重新核对，并与新任务派发互斥。重复点击复用同一次操作状态。超时或连接断开不证明工作结束，也不能据此重新启动。

停止服务后保留浏览器页面，页面显示断线，重新启动沿用既有重连机制；管理入口不自动关闭浏览器或丢弃草稿。

### 预约与恢复

未来预约提示“服务停止期间无法执行”，保留配置，不要求逐条删除或禁用。正在派发或执行的预约属于停机阻碍项；停机提交时阻止新派发。

用户接受了“重新启动沿用既有调度规则、不自动补跑错过任务”的表述；后续已经在 [停机后预约漏执行与既有策略的兼容边界](04-scheduled-misfire-policy.md) 确认其精确含义，调度兼容以该决策为准。

### 失败与更新

启动失败由浏览器等待页显示错误，托盘标明失败，默认不弹管理窗口。错误与日志保留；只有确认旧服务及 worker 实际退出，才允许手动重新启动。服务异常退出不自动重启或重放任务。

停机失败或长时间未完成时，明确显示“停机失败”或“仍在等待”，保留管理入口；不能提前显示“已停止”，不能自动强杀或重试。

更新仅提供版本信息和现有独立维护入口，不直接执行升级命令。

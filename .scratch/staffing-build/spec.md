# 人员调配第一版：实现规格

Status: ready-for-agent
Labels: ready-for-agent

## Problem Statement

调配负责人需要根据事业部和日期，为业务项目选择全程可用的人员。安排必须避免重复占用，并在每天达到最低人数、至少一名直签人员。当前工作台没有统一台账和确认流程，Excel 副本无法独立保证多个聊天看到相同的最新安排。

## Solution

增加默认关闭的内置人员调配能力。首次启用提供引导，创建并绑定专用智能体、配置配套 Skill 和工具、导入人员与占用并由用户核对。用户主要通过专用聊天查询和推荐，再通过具体卡片确认预占、正式安排或变更。三个辅助视图用于查人、看项目和看人员。模块台账为当前事实来源，Excel 按需导出并独立保存到成果中心。

本次用户调用 implement-spec，授权从需求讨论转入实现。此前“暂不制作”是历史阶段描述；既有业务确认继续有效。旧 wayfinder 保持决策跟踪记录，不把未解决的决策票伪装为已关闭的实施票。

## User Stories

1. 作为调配负责人，我要显式启用人员调配能力，以便普通工作台保持原有用途。
2. 作为调配负责人，我要通过引导创建专用智能体，以便无需手动拼装 Skill 和工具。
3. 作为调配负责人，我要重新启用时继续使用原台账和智能体，以便保留所有历史。
4. 作为调配负责人，我要导入和核对人员、当前及已知未来占用，以便正式调配有完整基线。
5. 作为调配负责人，我要用稳定人员编号区分重名人员，以便正确匹配和更新记录。
6. 作为调配负责人，我要维护事业部和直签标记，以便检查用人范围和直签要求。
7. 作为调配负责人，我要在聊天中提出项目、事业部、日期和人数需求，以便获得候选人员。
8. 作为调配负责人，我要默认只查本事业部，以便遵守日常调配范围。
9. 作为调配负责人，我要只对当前方案允许跨事业部借人，以便避免长期放开范围。
10. 作为调配负责人，我要日期包含首尾，以便避免同日重复安排。
11. 作为调配负责人，我要预占、正式安排、请假和培训都排除重复用人，以便候选人员全程可用。
12. 作为调配负责人，我要先看到完整推荐名单，以便调整后再决定是否预占。
13. 作为调配负责人，我要推荐本身不产生占用，以便自由比较候选方案。
14. 作为调配负责人，我要优先推荐用人开始日前九十天项目安排天数少的人，以便轮换使用人员。
15. 作为调配负责人，我要历史不足时明确提示，以便知道推荐依据的局限。
16. 作为调配负责人，我要通过列出人员、日期和缺口的卡片提交，以便确认对象明确。
17. 作为调配负责人，我要提交时再次检查最新台账，以便两个聊天不能重复占用同一个人。
18. 作为调配负责人，我要部分预占时持续看到人数和直签缺口，以便逐步补齐。
19. 作为调配负责人，我要人数达标和全部正式确认分开显示，以便避免混淆状态。
20. 作为调配负责人，我要改期、换人和释放前看到具体差异，以便确认后再改变原安排。
21. 作为调配负责人，我要临时请假先如实登记，再标记项目缺口，以便处理真实情况。
22. 作为调配负责人，我要缺口由我安排替补，以便系统不会自动调走其他项目人员。
23. 作为调配负责人，我要查询可用人员、项目和人员日历三个视图，以便核查调配情况。
24. 作为调配负责人，我要按需导出带时间和台账版本的 Excel，以便保存和交付安排。
25. 作为调配负责人，我要导出的文件保存到独立成果库，以便删除来源聊天后仍可使用文件。
26. 作为调配负责人，我要旧 Excel 导入先展示差异，以便旧表不能静默覆盖新安排。
27. 作为普通对话用户，我要其他智能体和无档案对话不加载人员调配提示、技能索引和工具定义，以便不增加无关上下文。
28. 作为调配负责人，我要断线后查询原操作结果，以便不重复提交不确定操作。
29. 作为调配负责人，我要停用时保留数据并关闭入口和工具，以便日后恢复。
30. 作为手机用户，我要卡片、抽屉和表单在窄屏正常使用，以便完成相同流程。

## Implementation Decisions

- 一个独立调配模块拥有全部业务状态。HTTP 和智能体工具共用它。模型处理需求表达，程序计算规则并保存结果。
- 第一版使用受保护的独立私密 JSON 台账，沿用现有原生安全文件与原子替换机制。能力状态、修订、人员、项目、占用、方案、历史和持久操作结果在同一次原子变更中保存。采用明确体积和记录数预算；超限明确失败，不截断当作完整台账。
- 稳定内部 ID 独立于姓名、显示名、工作目录和聊天身份。首次导入可生成 ID；后续导入按明确 ID 匹配，重名和不明确匹配交给用户核对。首次模板使用合成数据；真实清单稍后导入，不阻碍实现标准模板。
- 日期使用严格日历日期，包含首尾。近九十天窗口是项目开始日前的九十天，不包含项目开始日；项目预占与正式安排按人员和日期去重计数，取消安排排除，请假培训不计项目工作天数。同分按稳定编号排序。
- 覆盖统计按当天有效项目安排去重；请假培训覆盖的当天不能算在岗。允许真实请假与原项目记录并存，项目显示缺口并保留历史。
- 候选人满足整个请求日期范围。推荐先确保至少一名可用直签，再按约定顺序补足人数。人员不足时返回真实缺口，不虚构达标。
- 能力默认关闭。启用、初始化、待核对、就绪、停用的状态可查询。初始化持久记录业务绑定 ID，恢复时按绑定识别专用档案，保留用户自定义配置；不按名称猜测或重复创建。
- 专用智能体身份由原生会话绑定和服务端状态共同验证。资源发现和工具注册前过滤人员调配资源。其他新建对话不增加该能力的技能目录项、参数定义、使用指南或工具发现项；前端渲染代码不进入模型上下文。
- 卡片由前端根据后端方案生成。模型只需工具定义、工作步骤和必要结果摘要，不生成卡片 HTML/CSS。具体方案绑定台账修订、人员日期、跨事业部许可和来源上下文。用户的实际确认由受认证页面提交，模型填入确认布尔值不代替确认。
- 预占、确认、调整、释放和导入均使用稳定操作 ID 与预期修订。校验与提交串行；同 ID 同参数查询原结果，同 ID 异参拒绝。响应丢失只查询状态，不自动重发写请求。保存失败不报告成功。
- Excel 读取沿用有预算的 Office 解析边界，拒绝宏、外部引用执行和公式重算。导出使用标准 XLSX，固定工作表和机器可识别字段，写入明确值。日期和版本说明可见。后续导入先生成差异方案，再走相同确认通道。
- 成果留档沿用现有明确交付与独立保存语义，不向成果库绕过来源授权写入任意文件。生成、交付、已保存三种状态分别报告。成果保存失败不撤回已成功的人员安排。
- 新模块纳入实际活动、统一异步停机和备份边界。所有源码、技能和静态资源进入现有统一发现或公开清单，不建立第二套打包目录规则。
- 当前源码与用户已有版本元数据保持各自归属。本次不升版本、不发布、不重启承载执行的服务。集成在独立分支和隔离工作树完成。

## Testing Decisions

测试只观察公开行为，不直接查询私有存储内部结构来代替业务结果。以下三个测试层面和六张实施票已由用户确认。

1. 调配模块公开接口与 HTTP 入口：用独立身份与合成人员完成初始化、导入、查询、方案和提交；验证日期、人数、直签、请假、九十天计数、并发修订、操作结果核对、持久恢复及 Excel 往返。只经公开接口断言，不读取私有存储内部结构代替结果；捕获业务和持久化错误，不证明浏览器布局。
2. 受管会话与实际模型输入：在隔离会话和合成供应商中核对专用身份及普通身份的资源、工具定义和请求内容；验证普通对话无新增人员调配上下文。捕获加载与授权错误，不以提示词快照单独替代供应商实际请求。
3. Chromium 桌面与手机：用合成接口和独立测试服务完成启用引导、推荐、替换、卡片确认、缺口及导出；检查 pageerror、实际宽度、抽屉、附件和工具状态。验证关键真实装配链，禁止在维护中的真实聊天发送测试消息。

沿用项目统一 Node 和浏览器入口。每个行为先红后绿。最终因资源加载、会话、导航和共享装配均受影响，执行对应共享基础能力回归；文档及明确新增发行清单进行相应验证，不进行公开发行包验收或真实部署。

## Out of Scope

- 多用户账户、负责人分权审批、工资、考勤及劳动合同管理。
- 岗位、技能和证书筛选；自动调走其他项目人员。
- 金山文档在线同步、自动周期导出和通用资源调度平台。
- 修改上游依赖源码、安装真实身份资料、操作真实人员数据、部署、发布和版本升级。

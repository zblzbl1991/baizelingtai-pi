# 06：完成停用恢复、升级保留与整体验收

**Spec:** [合规审查实现规格草案](../spec.md)

**What to build:** 用户在完整审查流程中安全禁用和恢复能力，升级后保留档案与个人配置；工作台正确等待在途任务，资料、报告和普通聊天加载范围满足全部已确认要求。

**Blocked by:** [识别扫描资料并支持预算暂停与恢复](03-scans-budget-and-recovery.md)、[通过确认卡修正字段并确认结论](04-review-and-confirm.md)、[导出批次报告并保存到成果中心](05-reports-and-artifacts.md)。

**Status:** ready-for-agent

- [ ] 停用中、已禁用、配置不足、部分可用和可用状态对应真实工作，维护停机等待实际结束。
- [ ] 禁用保留业务数据及独立成果，重新启用不重建档案或自动重发请求，用户选择继续。
- [ ] 升级保留个人名称、行为说明和扩展，旧批次保留旧规则，新规则检查建立新批次。
- [ ] 普通聊天的实际模型请求不新增合规提示、工具定义或 Skill 索引，旧原生历史继续保留。
- [ ] 文档、API、模块说明、CHANGELOG、源码发现、资源登记和发行清单只记录已实现行为。
- [ ] 按共享基础能力范围完成 Node、语法、文档、真实 RPC、相关桌面/手机及要求的整体回归，不重启当前服务。
- [ ] 集成分支完成代码审查，修复发现的问题；真实资料或平台验收未执行时明确列为未完成。
- [ ] 所有实现票按实际结果记录完成，清理本次创建的实现工作树，报告集成分支与验证限制。

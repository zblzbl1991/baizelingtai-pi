# 02：导入文本资料并完成四组规则检查

**Spec:** [合规审查实现规格草案](../spec.md)

**What to build:** 用户从聊天附件或已授权目录导入文本资料与台账，核对归属及资料角色，创建批次，执行四组检查并在聊天中查看带原文位置的结果。原件变化后仍能追溯本次使用内容。

**Blocked by:** [启用能力并建立首个工程项目档案](01-enable-and-project.md)。

**Status:** done

- [x] 接收受支持的 PDF、图片、XLSX 和 UTF-8 CSV，扫描内容在识别能力尚不可用时明确列为无法判断；不支持的格式提示转换。
- [x] 导入范围与文件身份可核对，快照不可变，重复导入、同类多份和归属冲突有明确结果。
- [x] 项目身份和适用清单由用户核对，缺失资料、证据不足、不适用与执行失败分别显示。
- [x] 四组规则覆盖文号与日期精度，固定样例验证零、三十、三十一日、提前签订、同日及月份范围。
- [x] 批次保存实际资料与规则版本，按需查询明细和证据；结果 UI 不将未检查显示为通过。
- [x] 公开接口、专用工具及桌面/手机流程可从导入走到首份结果，且符合既有文件安全与容量预算。

## 实施与验证

- 同一业务账本保存资料、人工选用和固定批次；哈希原件不随源文件变化。目录、当前聊天附件与本机上传均核对范围，受控解析复用唯一办公文档解析池。单份 20 MiB、每工程 32 份/256 MiB、全部对象 2 GiB 的容量限制明确拒绝超限，不清理保留数据。
- 保守本地字段提取接受明确标签与 CSV/XLSX 固定表头。公式缓存、未知、冲突、截断或无法识别的资料不能产生确定性通过。发文首页上方位置保留真实旋转视口与文本坐标；空文本不能证明缺失。
- `test/pi-compliance-materials.test.js`：11 个受认证 HTTP 行为测试通过，含十二个独立日期样例、六类 PDF/图像文号与旋转/缺失情形、XLSX 公式与稀疏列、附件范围、快照重开、重复请求、容量拒绝及损坏快照执行失败。
- `test/pi-compliance-runtime.test.js`：真实受管 Pi RPC 与合成供应商捕获通过，含目录与原生分支附件导入、检查摘要、人工确认冒充拒绝、普通聊天资源隔离，以及密集 PDF 的普通 `read_document` 消费者兼容。
- 受影响 Node 选择首次 26/27 通过，唯一失败是现有 Windows PowerShell `Get-Acl` 模块加载；保留失败后，仅当前进程使用系统模块目录定向重验 `test/pi-document-uploads.test.js`，4/4 通过。没有放宽 DACL 断言。其余办公解析、真实文档 RPC 和原档案测试通过。
- Chromium 1440 浅色与 393 深色通过真实合规 HTTP 流程，含导入、角色/归属/版本、三十日通过与证据、丢失响应回执恢复、关闭后的迟到证据、草稿保留、宽度/pageerror，以及缺少安全上下文 API 时的请求 ID。截图人工核对。
- 语法 594 文件、公开文档 90 文件与 `git diff --check` 通过。仅完成源码与合成验收；扫描识别及预算恢复、字段和最终结论确认、报告仍由后续实施票负责。未部署、未发布或进行真实材料识别验收。

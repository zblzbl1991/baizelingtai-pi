# 05：导出批次报告并保存到成果中心

**Spec:** [合规审查实现规格草案](../spec.md)

**What to build:** 用户从指定批次按需生成 HTML 详细报告和 Excel 检查清单，在聊天中预览、下载并明确保存到独立成果中心，保留版本与复核状态。

**Blocked by:** [导入文本资料并完成四组规则检查](02-import-and-check.md)。

**Status:** done

- [x] 文件绑定固定的批次修订和规则版本，带生成时间、字段精度、证据及复核状态。
- [x] 完整列出问题、证据不足、不适用和执行失败，允许明确标识的未复核报告，不把导出等同于全部通过。
- [x] HTML 使用安全文本与受限制预览，XLSX 使用固定表头和明确值，可重新上传为文档附件后由已有读取接口核对；不以私密报告路径或成果 ID 直接绕过读取资格。
- [x] 生成、交付与已保存分别显示；原生交付引用由唯一受管 worker 登记，成果入库继续核对来源资格。
- [x] 不通过私密文件路径绕过文件权限，重复导出不覆盖旧文件，保存失败不修改批次结论。
- [x] 已保存成果在能力禁用或来源会话删除后仍可按现有成果权限查看。
- [x] 从专用聊天生成到预览、下载、保存的端到端流程在桌面和手机通过相关验证。

## 实现与验证

报告模块在同一合规账本中预占生成和交付意图，绑定固定批次修订；失败或未知对象保留预留，不覆盖、不自动重放。专用 worker 登记原生引用，独立保存继续使用既有成果来源校验。原始提取与已记录的人工值分列，系统结论、执行状态和人工决定分别保留。

在最终扫描模块集成 `fbc0d995` 后，报告 HTTP 两项通过，覆盖固定修订、幂等冲突、重开字节、失败与超限。真实 Pi RPC 加合成供应商验证报告工具、唯一原生引用、XLSX 重新上传与 `read_document`、停用后已接受交付确认、丢失确认后的关闭 worker 核对、独立保存及删除来源聊天后读取；新增停用确认用例先真实失败后最小修复通过。最终 Chromium 1440 明色与 393 暗色完整流程通过，核对空沙箱、下载、交付、独立保存、LAN 能力缺失、迟到证据、草稿、16px 表单、实际宽度及无 pageerror；截图已目视检查。
